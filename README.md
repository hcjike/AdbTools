# AdbTools

一款基于 WPF（C#）开发的 Windows 桌面工具，封装 ADB（Android Debug Bridge）常用命令，提供图形化界面实现 Android 设备的**无线连接、配对、设备管理、应用调试与实时远程控制**，无需记忆命令行。内置 `adb.exe`、远程控制所需的 scrcpy 设备端组件及依赖，开箱即用。

## 功能特性

- **无线连接**：输入 `IP:端口` 即可无线连接设备，支持省略端口（默认 `5555`）。
- **无线配对**：配对窗口内置「扫码配对 / 配对码」切换条（默认扫码）。扫码配对由工具生成二维码（协议同 Android Studio），手机端「使用二维码配对设备」扫码后自动完成配对、连接在后台静默尝试；也可切到「配对码」手动输入 `IP:端口` 与配对码配对。配对成功后直接关闭配对窗口，无需等待连接。
- **连接管理**：设备列表展示（`adb devices -l` 直接带出品牌与型号，设备一出现即可辨识，不必等属性读取），每行以 **USB（琥珀）/ WiFi（翠绿）** 徽标区分连接方式，并在下方显示**设备 SDK 版本**徽标；一键刷新（`F5`）、**定时刷新**（关闭 / 3 秒 / 5 秒 / 10 秒 / 15 秒 / 20 秒 / 30 秒 / 60 秒，设置自动保存）、断开单个 / 断开所有设备。
- **历史记录**：自动保存成功连接的地址，下拉框可右键「删除记录 / 清空所有记录」。
- **应用安装**：右键设备行「安装应用」选择 APK，或直接把 APK 文件**拖拽**到设备行。支持 `.apk`、`.apk.1` 等改名文件与文件夹递归收集（最多枚举 5000 个文件、最多加入 500 个 APK，按全路径去重，超限在状态栏提示）；进入**独立非模态**安装列表，后台解析应用名、包名、图标、大小、**版本号**与**最低 SDK 版本**，默认全选，支持全选 / 反选、随时**添加 / 删除**（删除二次确认），安装期间禁止增删；列表为空时显示引导提示，可直接点「添加」或把 APK 拖到列表区域。设备 SDK 随设备信息读取并显示在顶部，应用最低 SDK 高于设备时在列表中标红并标注「不兼容」、禁止勾选、悬停显示原因。安装中锁定选择并自动滚动到当前项，成功后自动取消勾选，失败与跳过项保留选中便于重试。列表下方仅在安装结束时显示一条结果汇总（成功绿 / 失败红 / 跳过橙），点击 `失败 N` 打开失败详情；中文路径与 adb 输出按 UTF-8 解码，安装明细按天写入日志。
- **应用列表**：独立窗口打开应用列表，显示应用名、包名、图标及系统服务、Debug、停用 / 卸载等状态，支持搜索与按状态筛选；复选框与 `Ctrl` / `Shift` 选择双向同步，普通单击不会误改选择，点击单行操作后自动恢复为仅选中当前项，避免操作对象不明确。顶部按「选择 / 操作」分组，按钮带标准悬停提示，未选择时点击操作按钮会在左下角给出红色提示。批量停用、启用、卸载、强制停止、清除数据、解析名称按顺序执行，只确认一次，支持执行中停止与结果汇总；系统应用卸载后仍保留在列表中，可一键恢复。同一台手机只保留一个列表窗口。
- **设备调试**：打开 Shell 窗口、独立日志窗口（缓冲切换、级别 / 关键字过滤、暂停、清空、保存、自动换行、选择复制）、一键抓取崩溃日志与诊断包、恢复默认 TCP 端口 / 分辨率 / DPI / 显示（分辨率 + DPI 一次恢复）。
- **文件管理**：独立窗口浏览设备文件（默认 `/sdcard`），顶部图标工具栏（返回上级 / 根目录 / SD 卡 / 临时目录 / 应用数据 / 刷新 / 路径跳转）配快捷键，支持把本地文件 / 文件夹**拖拽**上传、上传 / 下载**文件与文件夹**（含子目录，空文件夹也会创建）、新建文件夹、重命名、删除；`Ctrl` + 左键划过可快速多选。传输**逐文件执行**，遇到同名文件弹窗询问（覆盖 / 跳过 / 重命名，可勾选「为后续所有冲突执行此操作」），进度条显示「已完成 / 总数」并实时汇总已新增、已覆盖、已重命名、已跳过与失败数量，可随时「停止传输」；拖拽到列表时会先提示将上传的文件夹数与文件数。权限不足或分区只读会给出明确提示。列表按扩展名区分 **29 类文件图标**（文档、表格、压缩包、影音、源码、字体、证书、镜像、3D 模型等），可一眼分辨类型。
- **应用私有数据（免 root）**：工具栏「应用数据」列出全部第三方应用并探测可访问性；**左键双击**可调试应用进入其 `/data/data/<包名>` 目录后，可浏览、上传、下载、新建、重命名、删除，走 `run-as` 官方调试通道，不需要 root。应用列表层禁用这些文件操作，正式签名包标记为「不可访问」。
- **实时远程控制**：右键设备行即可打开实时画面窗口，支持触摸 / 滑动与返回、Home、任务、音量、电源等虚拟按键；设备端用 MediaCodec 主动编码（scrcpy server）输出 H.264，画面横竖屏自动适配。内置五档采集分辨率（原画 / 1080P / 720P / 480P / 360P），带清晰度图标与悬停说明；设备达不到的档位自动隐藏，编码器不兼容时**逐级向下验证**直到找到可用档位，最后仍不可用时自动回退 `adb screenrecord`。状态栏显示真实上屏帧率，启动与息屏在画面中央给出卡片提示；关闭窗口立即消失，停止取流与清理设备端服务在后台完成。同一台设备只保留一个远程控制窗口，重复打开会还原到前台。
- **操作日志**：独立日志窗口记录操作过程与状态，可右键复制命令。
- **托盘后台**：关闭主界面后收起到系统托盘继续后台刷新设备；设备连接 / 断开、安装结果、远程控制断开、配对结果可分别开关系统通知，**前台与后台都会提醒**；安装结果通知带设备名、耗时与逐条成功 / 失败明细，`安装结果` 通知被关闭或系统发不出去时会用对话框兜底，结果不会丢；`配对结果` 关闭或通知不可用时则完全静默；托盘右键菜单可显示主界面、刷新设备、直接打开某台设备的远程控制 / 应用列表 / Shell 窗口、断开指定设备或全部设备、检查更新与退出（直接退出，不再确认）。再次启动程序会唤出已收起的主窗口，不会产生第二个进程。
- **其它**：窗口置顶、最小化、关于信息、项目地址（含镜像）、检查更新（Gitea 仓库镜像）、关于菜单中直接打开程序运行日志目录。

## 开发环境

- 开发工具：Visual Studio 2019 / 2022
- 框架：`.NET Framework 4.6.2`
- 平台：`x64`
- 主要依赖：`QRCoder`（扫码配对）、`System.Data.SQLite`（应用缓存）、`Hardcodet.NotifyIcon.Wpf 2.0.1`（系统托盘与气泡兜底）、`Microsoft.Toolkit.Uwp.Notifications 7.1.3`（Windows 系统通知）、`libwebp`（图标解码）

## 运行环境

- 需要 `.NET Framework 4.6.2` 运行时（Win10 1607 及以上 / Win11 已内置，无需另装）；
- `64 位 Windows` 系统；
- 程序已内置 `adb.exe` 及依赖（`AdbWinApi.dll`、`AdbWinUsbApi.dll`、`QRCoder.dll`、`libwebp.dll`、`System.Data.SQLite.dll`）、远程控制所需的 `scrcpy-server` 与授权文件（`scrcpy-LICENSE.txt`、`THIRD_PARTY_NOTICES.txt`），以及本项目许可证 `LICENSE.txt`，**无需电脑另行安装 ADB、scrcpy 或 VC++ 运行库**，Windows 10/11 开箱即用。adb 命令会自动拉起自带服务，不依赖系统中已存在的 adb 服务（Win7/8/8.1 需系统已安装 Universal C Runtime 更新）；
- 远程控制要求设备允许 `adb shell` 以 shell 身份启动 `app_process`（部分深度定制的 TV ROM 会限制）；不满足时会自动回退到 `adb screenrecord`，功能仍可用但流畅度会下降。

## 连接准备

[观看视频](/docs/videos/1.mp4)

### 开启开发者模式

`设置 - 关于 - 版本号`，连续点击 `7 次` 开启开发者模式。

### 安卓 11 及以上

`设置 - 系统 - 开发者选项`，找到 `无线调试`，连接 WiFi 后开启，进入 `无线调试` 查看 `IP 地址和端口`，使用该地址即可无线连接。

> 注：部分设备入口位置不同，请自行寻找。

### 安卓 11 以下

连接 WiFi 后查看设备 `局域网 IP 地址`，使用该地址即可无线连接，此时无需输入端口号。

> 注：过低版本的设备可能无法连接。

## 安装和使用

提供自包含的单文件安装程序 `AdbToolsInstaller.exe`，具备以下特性：

- **单个 exe 直接安装**，无需先解压；
- 在「程序和功能」中始终保持**唯一条目**，不同版本不会重复出现；
- 升级时自动读取上次安装位置并**覆盖到原目录**；
- 在桌面与开始菜单创建名为 **`Adb连接工具`** 的快捷方式；
- 通过安装目录下的 `uninstall.exe`（或「程序和功能」）即可**干净卸载**。

安装包内含文件（安装后位于程序目录）：

| 文件 | 用途 |
| --- | --- |
| `AdbTools.exe`、`QRCoder.dll` | 主程序与扫码配对 |
| `Hardcodet.NotifyIcon.Wpf.dll` | 系统托盘图标与通知气泡（Toast 不可用时的兜底） |
| `Microsoft.Toolkit.Uwp.Notifications.dll` | Windows 10/11 系统通知（Toast） |
| `adb.exe`、`AdbWinApi.dll`、`AdbWinUsbApi.dll` | ADB 及 USB 依赖 |
| `libwebp.dll` | 应用图标 WebP 解码 |
| `System.Data.SQLite.dll`、`SQLite.Interop.dll` | 应用名 / 图标 / 系统服务缓存数据库 |
| `scrcpy-server` | 远程控制的设备端取流服务（运行时推送到设备 `/data/local/tmp/`） |
| `scrcpy-LICENSE.txt`、`THIRD_PARTY_NOTICES.txt` | 第三方许可证全文与许可/组件声明 |
| `LICENSE.txt` | 本项目 Apache-2.0 许可证全文（含版权声明） |
| `uninstall.exe` | 卸载程序 |

安装时会额外写入 `install.manifest` 记录本次释放的文件清单，卸载时按清单精确删除，不会误删目录内的其他文件。

重新生成安装包：在 Visual Studio 中直接生成 `AdbToolsInstaller` 项目（会自动编译主程序与卸载器、打包并嵌入 payload）。脚本 `build_payload.ps1` 会收集主程序输出目录下的全部 `*.exe` / `*.dll`（含 `libwebp.dll`、`SQLite.Interop.dll`）、运行配置 `AdbTools.exe.config`，以及上表中的非程序文件一并纳入 `payload.zip`。

### 软件更新

- 顶部「关于 → 检查更新」会从 Gitea 仓库镜像读取最新版本号与安装程序；
- 发现新版本时，顶栏右侧出现升级图标；确认更新后下载进度百分比显示在图标右侧（平时隐藏），鼠标悬停图标也可看到文字进度；
- 确认更新后，安装包下载到 `%APPDATA%\AdbTools\cache`（与其它临时文件统一管理，不占用 `%TEMP%`），下载完成自动启动安装程序并退出本程序；
- 覆盖安装会保留 `%APPDATA%\AdbTools\AdbTools.config` 中的配置与连接历史；
- 每次启动会清空 `cache` 目录，残留安装包不会累积；
- 下载目录位于当前用户目录，无需管理员权限；安装程序覆盖程序目录时按系统提示授权即可。

## 使用说明

### 设备配对（Android 11+）

配对窗口顶部提供「扫码配对 / 配对码」切换条，**默认进入扫码配对**。

**方式一：扫码配对（推荐，默认）**

1. 点击「配对 (`F8`)」打开配对窗口（默认即为扫码界面）；
2. 工具生成配对二维码（协议与 Android Studio 一致），上方高亮条提示手机操作路径；
3. 手机在「无线调试 - 使用二维码配对设备」界面扫描二维码，工具自动发现设备并完成配对；配对成功后配对窗口**直接关闭**（不弹提示），后台自动尝试连接（最多 3 次，无需等待），是否连上以设备列表为准。

> 注：部分老设备 ADB Wi-Fi 版本较低（v1.0）配对能力受限，扫码失败时请改用方式二。

**方式二：输入配对码**

1. 在配对窗口点击「配对码」切换到手动模式；
2. 在设备「无线调试 - 使用配对码配对设备」中获取 `IP:端口` 与配对码；
3. 输入**配对地址**与**配对码**，点击「配对 (`Enter`)」或按回车完成。

### 设备连接

1. 在「IP 和端口」输入框中输入设备的 `IP:端口`（可省略端口，默认 `5555`）；
2. 点击「连接 (`Enter`)」或按回车，等待连接成功。

### 历史记录

- 连接成功的地址会保存在下拉历史中；
- 展开输入框右侧下拉，右键某条记录可进行「删除记录 / 清空所有记录」。

### APK 安装列表

右键设备 →「安装应用」，或把 APK / 文件夹拖到设备行，即打开**独立非模态**的安装列表窗口。

**窗口结构**：顶部显示当前设备与 SDK 版本；中部是 APK 列表；底部左侧为「全选 / 反选 / 添加 / 删除」，中间显示「共 N 项 · 已选 M 项」，右侧为「开始安装 / 取消」。

**列表项**：左侧复选框与图标，右侧上下两行显示应用名与包名（单行超出省略，悬停提示完整应用名与文件路径）；下一行是「大小 / SDK ≥ N / 版本 X / 解析」四个徽标，最右是安装状态。应用名、图标、包名、版本号与最低 SDK 均在后台从 APK 读取，不下载整包，中文路径按 UTF-8 解码。

**空列表**：列表为空时显示「暂无 APK 文件」引导提示（含添加按钮与拖放说明），添加文件后自动切回列表。

**增删与去重**：「添加」支持多选文件，也可把 APK 或文件夹直接拖到列表区域追加（文件夹递归收集 `.apk`、`.apk.1` 等改名文件，最多枚举 5000 个文件、最多加入 500 个 APK，超出部分在状态栏提示）；两种入口都按**文件全路径**去重，重复项会提示“已添加过”。“删除选中”移除当前勾选的项，需二次确认。安装期间两个按钮与拖放均被锁定，并给出提示。

**SDK 兼容性**：设备 SDK 随设备信息一起读取并显示；每个 APK 的最低要求高于设备版本时，该项标红、状态显示「不兼容」、禁止勾选，悬停状态可看到「应用要求最低 SDK N、当前设备 SDK M」的具体原因，安装时自动排除，不会占用安装队列。

**安装与结果**：点击「开始安装」后锁定勾选、逐项串行安装并自动滚动到当前项；可随时取消，剩余项标记跳过。成功后自动取消勾选，失败与跳过项保留选中，点「再次安装」只重试这些项。安装结束后列表下方才出现一条居中的结果汇总，点击「失败 N」打开详情窗口查看每个应用的图标、名称、包名与失败原因，支持单项 / 全部复制。

### 应用列表

右键设备 →「应用列表」。列表以**独立窗口**打开，不依附主界面，可单独最小化或拖到另一块屏幕；同一台手机只保留一个窗口，重复点击会把已打开的窗口带到前台。

**选择与批量操作**：每行左侧复选框可勾选，也支持 `Ctrl` / `Shift` 选择并同步复选框；普通单击不会误改选择状态。点击行内「停用 / 启用 / 卸载 / 更多」等操作后，会自动恢复为仅选中当前项，避免不清楚操作对象。顶部左侧是「全选 / 反选 / 清空选择」，右侧是「停用 / 启用 / 卸载 / 强制停止 / 清除数据 / 解析名称」，按钮带标准鼠标悬停说明；未选择就点击操作按钮时，底部状态栏显示红色提示。批量操作按顺序逐项执行，只确认一次，完成后汇总成功 / 失败数量与失败原因，执行中可点「停止操作」在当前命令结束后退出；清除数据期间会暂停应用名解析，避免争抢设备 IO。

包名与状态来自设备端命令，但**应用名需要额外拉取数据**：

- **包名与状态**：`pm list packages -f` 取包名与 APK 路径，`-s` / `-d` 标记系统应用与已停用应用，`-u` 用于发现已从手机上移除的系统应用，返回很快。
- **应用名**：Android 没有直接查询应用名的命令，只能读取每个应用 APK 内的 `AndroidManifest.xml` 与 `resources.arsc`，在本机解析 `android:label`，并优先取简体中文资源。
- **系统服务**：解析 manifest，把系统应用里「无桌面入口」或「声明常驻（persistent）」的应用标记为「系统服务」，列表以橙色标签显示并支持筛选。
- **Debug 标记**：从 `dumpsys package` 的 `DEBUGGABLE` 标志读出，显示为绿色标签，可用「Debug 应用 / 非 Debug 应用」筛选。列表先显示、标记后异步回填，不阻塞；每次刷新重新读取，不用缓存。标签只表示 manifest 声明了 debuggable，不代表 run-as 一定能进入私有目录。
- **图标**：与名称一起解析，取 APK 里最高密度的图标位图；自适应图标（`mipmap-anydpi-v26/*.xml`）会再读它的前景层；WebP 与矢量图（VectorDrawable）图标由本机解码 / 渲染后缓存。解析不到图标的少数应用显示「包名首字 + 固定色块」占位，取到图标后色块自动隐藏（透明背景的图标不会透出底色），不影响其它信息。
- **拉取量**：每个应用只取 manifest、资源表和一张图标（多数几十 KB 到几百 KB，**不下载整个 APK**）。325 个应用首次约需 1~2 分钟，状态栏显示进度；可随时点「停止获取名称」中断，关闭窗口也会立即停止。
- **大应用较慢**：资源表特别大的应用（例如系统「设置」约 104MB）单个约需 1 分钟；超过 160MB 的直接跳过，只显示包名。
- **缓存按设备隔离**：名称、系统服务标记、解析状态与图标都存在 `%APPDATA%\AdbTools\data\AdbTools.db`（SQLite），并按设备键分开。同一个包在不同手机上名称/图标不同时各自保存，互不覆盖；来自缓存的行会在列表中以「缓存」标签标注。
- **图标去重**：图标内容按 SHA1 存一份，多个应用共用同一张图（或同一应用在多台设备上图标相同）只占一份空间；无人引用的图标会在下次打开列表时清理。
- **解析名称**：右键某个应用可选「解析名称」，顶部也支持对已选应用批量解析；会忽略已有缓存与失败标记、从设备重新解析并覆盖，用于应用更新后名称变了的情况。
- **远程控制窗口尺寸**：手动调整过的窗口**大小**按设备保存在同一个库（横屏、竖屏各一份），下次打开同一台手机直接沿用；不记位置，恢复时按屏幕居中并把尺寸限制在工作区内，不会跑到屏幕外。
- **设备键**：依次取 `ro.serialno` → `ro.boot.serialno` → `android_id`，都由设备自身返回，同一台手机用 USB / IP / 无线调试连接时结果相同，因此多种连接方式共用一份缓存；三者都取不到时才退回连接序列号（此时各连接方式会各存一份）。硬件序列号在设备列表刷新时与品牌型号一并读取，打开应用列表、远程控制时直接使用，不再额外发命令。
- **库结构**：当前为 v2（v2 相比 v1 只新增远程控制窗口尺寸表），升级时原有缓存不受影响。
- **仍显示包名的情况**：少数系统包（如部分 apex 虚拟化组件）本身没有 `android:label`，只能显示包名。
- **不影响操作**：名称只用于显示，卸载 / 停用 / 启用 / 清除数据等功能随时可用，不必等名称解析完成。
- **WiFi 调试注意**：数据经 adb 通道传输，WiFi 下会占用带宽；解析期间同时使用远程控制可能互相影响，可先点「停止获取名称」。

### 文件管理

右键设备 →「文件管理」（托盘菜单同样有入口），以独立窗口浏览设备文件，同一台设备只保留一个窗口。

**顶部工具栏**按功能分四组（竖线分隔）：

| 分组 | 按钮 | 说明 |
| --- | --- | --- |
| 导航 | 返回上级 / 根目录 / SD 卡 / 临时目录 / 应用数据 / 刷新 | 分别跳到上级目录、`/`、`/sdcard`、`/data/local/tmp`、应用私有数据列表、刷新当前目录；已在 `/` 时「返回上级」按钮禁用 |
| 地址 | 路径输入框 + 箭头 | 输入路径后按 `Enter` 或点箭头跳转 |
| 文件操作 | 新建文件夹 / 上传文件 / 上传文件夹 / 下载 | 目标都是当前目录 |
| 修改 | 重命名 / 删除 | 作用于选中项，删除不可恢复 |

**快捷键**

| 按键 | 作用 |
| --- | --- |
| `Enter` | 在路径输入框中跳转到输入的路径 |
| `F5` | 刷新当前目录 |
| `Backspace` | 返回上一级 |
| `Delete` | 删除选中项（二次确认，不可恢复） |
| 双击 | 文件夹进入；文件直接下载 |
| `Ctrl` / `Shift` + 单击 | 追加 / 连续多选 |
| `Ctrl` + 按住左键划过 | 划过经过的项逐个追加选中 |

> 所有窗口的滚动条统一收窄为 8px。

- **浏览**：默认打开 `/sdcard`；左键双击文件夹进入，双击符号链接时先解析目标，指向目录就进入、指向文件则下载。右键只出菜单，不进入。
- **重新获取名称 / 图标**：在「应用数据」列表里右键单个应用，只重新解析这一项并覆盖缓存，不重列整个列表。
- **上传**：「上传文件」可一次选多个文件，「上传文件夹」上传整个目录，目标都是当前目录；也可直接把本地文件 / 文件夹**拖拽**到文件列表区域上传。目录会逐层创建设备端文件夹（**空文件夹同样会创建**），子目录结构完整保留。
- **下载**：选中一项或多项后点「下载」，再选择本地目录；下载文件夹同样保留子目录结构（会在目标目录下创建同名文件夹），空文件夹也会创建。**文件夹名含逗号**同样可以正常下载（逐文件取回后在本地还原目录结构）。
- **新建 / 重命名 / 删除**：顶部对应按钮，删除会二次确认并列出待删项目。
- **传输方式**：上传 / 下载都是**逐文件执行**。开始前先扫描出文件总数，进度条（胶囊造型）中显示「已完成 / 总数」，状态栏显示当前文件名与分类统计；可随时点右下角「停止传输」中止整批。失败项会汇总提示（最多列出 10 项），停止后设备端可能残留半个文件。
- **拖拽提示**：把本地内容拖到列表区域时，中央会提示「松手上传 N 个文件夹、M 个文件」；不含可上传内容、正在传输或处于应用列表时给出对应的红色提示，且不允许放下。空目录提示层同样可直接拖放上传。
- **权限**：`/sdcard`、`/sdcard/Download`、`/sdcard/DCIM` 等可直接读写；`/data/local/tmp` 属 `shell` 用户，是系统分区里唯一可自由读写的位置（常用作脚本与 APK 的中转）；`/data/data`、`/data/system` 是应用私有数据，普通 shell 无权限，可改用「应用数据」入口（限可调试应用，见下节）；`/system`、`/vendor` 只读，写入会提示分区只读。
- **图标**：按扩展名区分 **29 类矢量图标**（文档 / 表格 / 演示 / PDF / 电子书 / Markdown / 网页 / 配置 / 字体 / 二进制 / 脚本 / 证书 / 字幕 / 镜像 / 3D 模型 / 设计稿 / 日历 / 联系人 / 图片 / 视频 / 音频 / 压缩包 / APK / 数据库 / 源码等），未知类型用普通文件图标；文件夹与符号链接各有专用图标。
- **提示位置**：无权限、目录不存在、空目录等结果会**直接显示在列表区域中央**（含路径、原因与处理建议），并提供「返回上级 / 刷新」按钮。
- **注意**：WiFi 连接下大批量传输会占用带宽，同时使用远程控制会掉帧；传输过程中关闭窗口会先确认再取消。

### 同名文件冲突

上传或下载时，如果目标位置已存在同名**文件**，会弹出冲突询问窗口（同名文件夹直接合并，不询问）：

| 选项 | 说明 |
| --- | --- |
| 覆盖 | 用源文件替换目标文件 |
| 跳过 | 保留目标文件，跳过这一项 |
| 重命名 | 保留两者，自动生成不重名的新名字（如 `报表 (1).xlsx`） |
| 停止传输 | 中止本次全部传输（只跳过当前文件请点「跳过」） |

- 窗口显示**源**与**目标**两侧的文件名、大小与修改时间，并用「电脑端 / 设备端」标识区分目标在哪一侧（上传时目标在设备端，下载时目标在电脑端）；
- 类型不一致（目标处是文件夹、源是文件）时不提供「覆盖」，只能跳过或重命名；
- 「为后续所有冲突执行此操作」**默认不勾选**，勾选后本批剩余冲突统一按本次选择处理；
- 结束后的汇总分别统计 **已新增 / 已覆盖 / 已重命名 / 已跳过 / 失败**，各项相加等于已完成数。

### 应用私有数据（免 root）

`/data/data` 属 `root` 所有，`adb shell` 连列目录都不允许，所以无法像普通目录那样逐级点进去。工具栏「应用数据」按钮改为两级视图：

1. 进入后列出设备上的**全部第三方应用**，并逐个用 `run-as <包名> id` 探测可访问性（4 个并发，十几二十个应用约 1 秒）；可访问的排在前面并显示 uid，不可访问的灰显、标「需 root」。
2. 左键双击可访问的应用进入它的 `/data/data/<包名>`，之后浏览、新建、重命名、删除、上传、下载都以**该应用自身身份**执行。右键用于「重新获取应用名与图标」，不进入。

| 能力 | 说明 |
| --- | --- |
| 前提 | 应用必须是**可调试（debuggable）包**（`android:debuggable="true"`），这是 Android 官方 `run-as` 通道的限制；微信、银行等正式签名包读不到，需要 root 设备 |
| 浏览 | 目录、文件、权限、大小、时间与普通视图一致；文件操作需先双击进入应用目录 |
| 下载 | 走 `adb exec-out run-as <包名> cat` 二进制流，数据库 / 图片 / 二进制文件都不会损坏；**整目录下载暂不支持**，请在目录内选择具体文件 |
| 上传 | 先 `adb push` 到 `/data/local/tmp`，再以应用身份 `cp` 进目标目录，落地文件属主就是该应用本身，应用可正常读写 |
| 返回 | 应用目录根再「返回上级」回到应用列表（root 设备同样如此，不会落到 `/data/data`）；点「根目录 / SD 卡 / 临时目录」或在路径框输入应用目录之外的路径，会自动退出应用身份、恢复普通 shell |
| 安全提示 | 删除、重命名会二次确认并提示「这是应用私有数据，可能导致应用崩溃或数据丢失」 |

### 卸载与恢复

- **系统应用**：卸载走 `pm uninstall --user 0`，只是从当前用户下移除，**系统分区里的安装文件不会被删除**。刷新列表后，可在筛选「已卸载应用」里找到它，点「恢复」用 `pm install-existing` 装回来，不需要重新下载 APK；但账号与登录状态已被清除。若只想暂时隐藏并保留数据，应改用「停用」。
- **第三方应用**：卸载是完整卸载，APK 与数据一并删除，不可撤销，也不会出现在「已卸载应用」里。
- **恢复的前提**：安装文件仍在系统分区（`/system`、`/system_ext`、`/product`、`/vendor`、`/odm`、`/apex`）。极少数被厂商 OTA 精简掉的组件、或系统版本过低没有 `install-existing` 命令的设备，恢复会失败并给出具体原因提示。
- **已卸载行的显示**：状态标签为「已卸载」，「卸载」按钮隐藏，主操作按钮变为「恢复」。

### 操作日志

点击菜单「查看日志」或右键设备的日志项，弹出「操作日志」窗口，记录每次操作的结果与状态；右键日志可「复制命令」便于排查。

### 设备日志窗口

右键设备 →「查看日志 → 实时日志」打开独立日志窗口：

- **缓冲**：main 主日志 / system 系统 / crash 崩溃 / events 事件 / 全部缓冲；鼠标悬停每一项可查看该缓冲的用途说明。
- **级别**：全部级别 / Debug 及以上 / Info 及以上 / Warn 及以上 / Error 及以上，按 logcat 级别字段过滤。
- **过滤**：按关键字筛选（不区分大小写），修改后自动从最近 5000 行原始日志重建视图。
- **自动换行**：底栏复选框，开启后长日志按窗口宽度换行、不再出现横向滚动条；状态写入全局配置，下次打开沿用。
- **自动滚动**：开启时只显示最近 5000 行并跟随底部；关闭后停止从顶部裁剪，显示上限临时放宽到 20000 行便于回看，重新开启会回到最近 5000 行并跳到底部。窗口打开时只取最近 200 行历史后跟随，避免瞬间涌入大量日志；adb 进程启动与日志读取均在后台线程，减少打开时卡顿。
- **暂停 / 继续**：暂停后仍继续接收，只冻结显示。
- **清空**：清空当前显示，并同步清空设备端对应缓冲区（有确认提示）。
- **保存**：导出当前显示内容到 `%APPDATA%\AdbTools\DeviceLogs\<设备名称>\`。
- **选择与复制**：
  - 单击选中一行，`Shift + 单击` 连续多选，`Ctrl + 单击` 点选多行；
  - `Ctrl + C` 复制选中行（未选中时复制当前显示的全部），按显示顺序输出；
  - `Ctrl + A` 全选。
- **颜色**：按 Android Studio logcat 配色区分级别——V 灰、D 蓝、I 绿、W 橙、E 红、F/A 紫；`[adb]` 错误输出为红色。
- **抓取崩溃日志 / 诊断包**：「查看日志」菜单中，诊断包包含 logcat、crash、dropbox、内存 / CPU 与设备信息，打包为 zip。
- 接收缓存最多保留 20000 行原始日志，正常显示上限 5000 行（关闭自动滚动时最多 20000 行），超出后按 FIFO 丢弃最早的行；关闭窗口时会结束对应的 adb 进程。

### 设置与关于

- **设置**：
  - **置顶显示**：鼠标划过在右侧展开二级菜单，**单选**`启用` / `关闭`，当前状态打对号；选择后立即生效并写入配置，下次启动沿用；
  - **定时刷新**：鼠标悬停「定时刷新」即在右侧展开间隔选项（关闭 / 3 秒 / 5 秒 / 10 秒 / 15 秒 / 20 秒 / 30 秒 / 60 秒），当前生效的间隔项前打勾；选择后自动保存并在下次启动沿用；定时刷新在后台静默执行，不显示加载动画。
  - **消息提醒**：鼠标划过即在右侧展开二级菜单，**多选**要接收的系统通知——`设备连接/断开`、`安装结果`、`远程控制断开`、`配对结果`（默认全开），点击即切换并立即保存，菜单保持展开便于连续勾选，每一项都有悬停说明；其中「设备连接/断开」依赖设备列表刷新，需手动刷新（`F5`）或开启「定时刷新」才会发现变化。
  - **通知规则**：通知**不在前台被抑制**，窗口开着也照常提醒；是否提醒只由这四项开关与 Windows 的通知设置决定，程序不做其它判断。`安装结果` 被关闭、或通知渠道不可用（系统过低、接口异常）时会改用**对话框**展示安装明细，结果不会丢；`配对结果` 关闭、或通知发不出去时都**不再做任何提醒**（配对成功后会自动尝试连接，以设备列表为准）。
  - **关闭方式**：鼠标划过在右侧展开二级菜单，**单选**——`最小化到托盘`（默认，已打开的远程控制与应用列表窗口不受影响）或 `直接退出程序`（退出前二次确认），选定后菜单自动收起。
- **关于**：
  - **项目地址**：GitHub 主页（源码浏览）；
  - **项目地址（镜像）**：Gitea 仓库（`code.hcjike.com`）；
  - **检查更新**：从 Gitea 仓库的 Releases 拉取最新版本信息与安装包，发现新版本时提示更新；安装包下载到 `%APPDATA%\AdbTools\cache`，安装后下次启动自动清理；
  - **打开日志**：直接打开程序运行日志目录 `%APPDATA%\AdbTools\logs`；与「查看日志 → 打开日志目录」（设备日志目录）不同。

## 远程控制

右键已连接设备 →「**远程控制**」打开实时画面窗口；多台设备可各自独立开窗口，互不影响。

### 窗口布局

- **顶部**：左侧状态栏只显示 `画面分辨率 → 设备物理分辨率   上屏帧率`；右侧是 **1:1 按钮**与清晰度下拉框（每项带图标，悬停可查看清晰度 / 速度 / 建议说明）。点「1:1」会把窗口调整到当前输出画面的像素尺寸，画面 1 像素对应屏幕 1 像素（高 DPI 下按实际缩放换算）；屏幕放不下时自动缩小并提示实际比例，达到 1:1 时也会提示。
- **中部**：实时画面，横竖屏切换时窗口按新比例自动调整并重新居中；**手动调整过窗口大小后不再自动改尺寸**，横屏与竖屏各记住一份**大小**并按设备保存，下次打开同一台手机直接沿用（恢复时居中且不超出屏幕），切换清晰度也不影响；首帧前与设备息屏时会在画面中央显示同款状态卡片。
- **底部**：返回 / Home / 任务 / 音量 / 电源 虚拟按键。音量键**按住持续调大 / 调小**（松开即停，不限次数）；电源键按住 **< 0.5 秒**为短按（亮屏 / 灭屏），**≥ 0.5 秒**松开时按长按处理（注入 `--longpress`）。
- **输入**：点击、拖拽与虚拟按键走 scrcpy 控制通道，按下即注入、拖动时逐条发送移动事件，延迟为毫秒级；控制通道不可用时自动回退 `adb shell input`，此时拖拽改为松手后一次性滑动。
- **滚轮**：在画面上滚动会转换为一次短距离滑动，抬手后由系统产生惯性；连续滚动会合并成一次手势，避免命令排队。

### 清晰度档位

| 档位 | 长边 | 特点 | 建议场景 |
| --- | --- | --- | --- |
| 原画 | 不缩放 | 最清晰，编解码与带宽开销最高 | USB、需要看清细节或截图取材 |
| 1080P 超清 | 1920 | 清晰度很高，开销约为原画的一半 | USB 或 5G Wi-Fi，兼顾清晰与流畅 |
| 720P 高清 | 1280 | 清晰够用，开销约为原画的 1/4 | 2.4G Wi-Fi、低配电脑、设备性能较弱 |
| 480P 标清 | 854 | 偏糊，小字可能看不清 | 网络较差、只需点击操作和看大致画面 |
| 360P 流畅 | 640 | 最低开销，只能看清大块内容与图标 | 网络差、设备性能弱，或只操作界面 |

程序会按设备原生分辨率**自动隐藏根本达不到的高档位**（例如 720P 屏不会列出 1080P）；若某档位的编码器不兼容，会**逐级向下实际验证**并移除失败档位，直到找到能正常出画面的档位。设备完全不支持 scrcpy server 时自动回退 `adb screenrecord`。

### 状态与指标

- 状态栏帧率统计的是**真正写进画面的帧数**（不是解码输出数），并按真实经过时间计算；悬停可查看上屏 / 解码帧率与上屏延迟的说明。画面静止时设备端不产帧，显示 `0 fps` 属正常现象。
- 锁屏但屏幕仍亮时继续取流，方便在锁屏界面上滑动解锁；息屏时画面中央提示「设备已息屏」。
- 启动过程与息屏提示以中央卡片告知；关闭窗口时窗口**立即消失**，停止取流、清理设备端服务与 adb 转发全部转到后台完成，主界面不会卡顿。同一台设备只保留一个远程控制窗口，重复打开会把已有窗口还原到前台。

## 常见问题

- **连接失败**：确认设备与电脑在同一局域网，开发者选项与无线调试已开启，且 IP/端口正确。
- **无法识别设备**：Android 11+ 需先完成配对再连接；旧版本系统可能不支持无线连接。
- **配对窗口自动关闭**：配对成功时配对窗口会**直接关闭且不弹提示**，属正常现象；此时后台会自动尝试连接（最多 3 次）并刷新列表，**能否连上以设备列表为准**——若列表中未出现该设备，请稍后点击「刷新 (`F5`)」或重新「连接」；如需重新配对，再次点击「配对 (`F8`)」即可。若窗口未关闭并给出提示，则说明配对失败，按提示检查地址、配对码或网络。
- **程序无法启动**：请确认已安装 `.NET Framework 4.6.2` 运行时（Win10 早期版本与 Win7/8.1 需自行安装）。
- **安装列表显示「不兼容」**：该 APK 声明的最低 SDK 高于当前设备系统版本，安装到这台设备上会被系统拒绝，因此列表标红、禁止勾选并自动排除；悬停该项的状态徽标可看到要求的最低 SDK 与设备当前 SDK。请更换兼容该设备的应用，或升级设备系统版本。
- **添加 APK 时提示「已添加过」**：安装列表按**文件全路径**去重，同一路径的 APK 不会重复加入；若确实要安装同一应用的另一个副本，请选择不同路径的文件。
- **找不到程序入口**：安装完成后，可从桌面或开始菜单的 **`Adb连接工具`** 快捷方式启动。
- **文件管理里 `/data/data` 打不开**：这是系统保护的应用私有目录，`adb shell` 连列目录都不允许。可点工具栏「应用数据」，以 `run-as` 访问**可调试（debug 包）应用**的私有目录，不需要 root；正式签名包（微信、银行等）与系统应用读不到，需要 root 设备。
- **看不到系统通知**：先确认「设置 → 消息提醒」里对应开关是打开的，再检查 Windows「设置 → 系统 → 通知」中 `Adb连接工具` 未被关闭；通知中心里显示的应用名由 AUMID 决定，程序启动时会固定写成 `Adb连接工具`。横幅停留多久由「辅助功能 → 显示通知的时长」控制，通知中心里的历史记录不会自动清除（属系统设计）。
- **安装结果只弹了对话框**：说明「安装结果」通知被关闭，或系统通知渠道不可用，程序自动改用对话框展示同样的明细，属预期兜底行为。
- **文件管理下载文件夹后多了一层同名目录**：下载文件夹时会在选定目录下创建同名文件夹并放入内容，这是保留原目录结构的预期行为。
- **上传同名文件时被反复询问**：这是逐文件处理的结果，遇到同名文件会逐项询问；不想逐个处理时勾选「为后续所有冲突执行此操作」，或用「跳过 / 重命名」批量处理。同名**文件夹**不会询问，直接合并。
- **点「停止传输」后计数没变**：被中止的那一项不计入任何统计（既不算跳过也不算失败），汇总里的已完成数只包含真正处理完的文件。
- **远程控制画面几秒才变一次**：静止界面设备端本来就不产帧（帧率会显示 `0 fps`）；若播放视频时画面区域仍是黑的，通常是 DRM 安全图层，软件层无法捕获，只能改用 HDMI 采集卡。可先切到「设置」等持续动画的纯 UI 页确认。
- **TV 机顶盒远程控制不流畅**：优先手动切到 720P、480P 或 360P；程序也会在编码器不兼容时自动逐级降档。若日志提示「回退到 screenrecord」，说明该 ROM 限制了 `app_process`，属兼容兜底。
- **清晰度下拉里少了几个档位**：设备原生分辨率达不到的档位会在启动时隐藏，验证失败的档位会被移除，属正常行为。
- **远程控制提示「系统缺少媒体组件」**：当前系统未包含 Media Foundation（常见于 Windows N / KN 版或精简系统），安装系统对应的「媒体功能包」后即可正常取流；与设备连接无关，不必反复检查数据线或网络。
- **帧率正常但操作有粘滞感**：状态栏显示的是真实上屏帧率；粘滞主要来自设备端采集编码与 adb 往返（约 100~200 ms），切到更低的分辨率档位可缓解。
- **关闭远程控制窗口后设备端还残留一会儿服务**：关闭时窗口立即消失，停止取流与清理设备端服务、adb 转发在后台进行（通常 1~3 秒），期间设备端服务可能短暂残留，属正常现象。
- **点了 × 程序没有退出**：程序默认收起到系统托盘继续后台运行，右键托盘图标选择「退出」才会真正退出；也可在「设置 → 关闭方式」里选「直接退出程序」。
- **日志在哪里**：远程控制日志 `%APPDATA%\AdbTools\logs\RemoteControl-yyyyMMdd.log`、应用列表日志 `%APPDATA%\AdbTools\logs\AppList-yyyyMMdd.log`、APK 安装日志 `%APPDATA%\AdbTools\logs\Install-yyyyMMdd.log`、程序异常日志 `%APPDATA%\AdbTools\logs\AppException-yyyyMMdd.log`（未捕获异常会先写日志再弹提示，按天分文件，每类自动保留最近 7 份）；只有当天确实产生日志时才创建对应日志文件；抓取的设备日志与诊断包位于 `%APPDATA%\AdbTools\DeviceLogs\<设备名称>\`；配置与设备历史位于 `%APPDATA%\AdbTools\AdbTools.config`；应用数据（应用名与图标缓存）位于 `%APPDATA%\AdbTools\data\AdbTools.db`；所有临时文件统一放在 `%APPDATA%\AdbTools\cache`，每次启动自动清空，不会写到系统临时目录。
