# AdbTools

一款基于 WPF（C#）开发的 Windows 桌面工具，封装 ADB（Android Debug Bridge）常用命令，提供图形化界面实现 Android 设备的**无线连接、配对、设备管理、应用调试与实时远程控制**，无需记忆命令行。内置 `adb.exe`、远程控制所需的 scrcpy 设备端组件及依赖，开箱即用。

## 功能特性

- **无线连接**：输入 `IP:端口` 即可无线连接设备，支持省略端口（默认 `5555`）。
- **无线配对**：配对窗口内置「扫码配对 / 配对码」切换条（默认扫码）。扫码配对由工具生成二维码（协议同 Android Studio），手机端「使用二维码配对设备」扫码后自动完成配对、连接在后台静默尝试；也可切到「配对码」手动输入 `IP:端口` 与配对码配对。配对成功后直接关闭配对窗口，无需等待连接。
- **连接管理**：设备列表展示（`adb devices -l` 直接带出品牌与型号，设备一出现即可辨识，不必等属性读取）、一键刷新（`F5`）、**定时刷新**（关闭 / 3 秒 / 5 秒 / 10 秒 / 15 秒 / 20 秒 / 30 秒 / 60 秒，设置自动保存）、断开单个 / 断开所有设备。
- **历史记录**：自动保存成功连接的地址，下拉框可右键「删除记录 / 清空所有记录」。
- **应用安装**：右键设备行「安装应用」选择 APK，或直接把 APK 文件**拖拽**到设备行安装（拖入文件夹会递归查找）。支持 `.apk` 以及微信、QQ 等分发工具改名后的 `.apk.1` / `.apk.2` 文件；安装确认窗口从安装包内读取**应用名与包名**，不必靠文件名猜，解析不到时回退显示文件名。
- **应用控制**：独立窗口打开应用列表，查看全部应用（图标 / 应用名 / 包名 / 系统或第三方 / 系统服务 / 停用或卸载状态），支持搜索与按状态筛选，可直接卸载、停用 / 启用、清除数据；系统应用卸载后仍保留在列表中，可一键恢复。同一台手机只保留一个列表窗口。
- **设备调试**：打开 Shell 窗口、独立日志窗口（缓冲切换、级别 / 关键字过滤、暂停、清空、保存、选择复制）、一键抓取崩溃日志与诊断包、恢复默认 TCP 端口 / 分辨率 / DPI。
- **文件管理**：独立窗口浏览设备文件（默认 `/sdcard`），支持上传 / 下载**文件与文件夹**（含子目录）、新建文件夹、重命名、删除；传输过程有进度显示与「取消传输」，权限不足或分区只读会给出明确提示。
- **实时远程控制**：右键设备行即可打开实时画面窗口，支持触摸 / 滑动与返回、Home、任务、音量、电源等虚拟按键；设备端用 MediaCodec 主动编码（scrcpy server）输出 H.264，画面横竖屏自动适配。内置五档采集分辨率（原画 / 1080P / 720P / 480P / 360P），带清晰度图标与悬停说明；设备达不到的档位自动隐藏，编码器不兼容时**逐级向下验证**直到找到可用档位，最后仍不可用时自动回退 `adb screenrecord`。状态栏显示真实上屏帧率，启动与息屏在画面中央给出卡片提示；关闭窗口立即消失，停止取流与清理设备端服务在后台完成。同一台设备只保留一个远程控制窗口，重复打开会还原到前台。
- **操作日志**：独立日志窗口记录操作过程与状态，可右键复制命令。
- **托盘后台**：关闭主界面后收起到系统托盘继续后台刷新设备，设备连接 / 断开、安装结果、远程控制断开可用系统通知提示（可在设置里分别开关）；托盘右键菜单可显示主界面、刷新设备、直接打开某台设备的远程控制 / 应用列表 / Shell 窗口、断开全部设备、检查更新与退出（退出前二次确认）。再次启动程序会唤出已收起的主窗口，不会产生第二个进程。
- **其它**：窗口置顶、最小化、关于信息、项目地址（含镜像）、检查更新（Gitea 仓库镜像）。

## 开发环境

- 开发工具：Visual Studio 2019 / 2022
- 框架：`.NET Framework 4.6.2`
- 平台：`x64`
- 主要依赖：`QRCoder`（扫码配对）、`System.Data.SQLite`（应用缓存）、`Hardcodet.NotifyIcon.Wpf 2.0.1`（系统托盘与通知）、`libwebp`（图标解码）

## 运行环境

- 需要 `.NET Framework 4.6.2` 运行时（Win10 1607 及以上 / Win11 已内置，无需另装）；
- `64 位 Windows` 系统；
- 程序已内置 `adb.exe` 及依赖（`AdbWinApi.dll`、`AdbWinUsbApi.dll`、`QRCoder.dll`、`libwebp.dll`、`System.Data.SQLite.dll`）、远程控制所需的 `scrcpy-server` 与授权文件（`scrcpy-LICENSE.txt`、`THIRD_PARTY_NOTICES.txt`），以及本项目许可证 `LICENSE.txt`，**无需电脑另行安装 ADB、scrcpy 或 VC++ 运行库**，Windows 10/11 开箱即用。adb 命令会自动拉起自带服务，不依赖系统中已存在的 adb 服务（Win7/8/8.1 需系统已安装 Universal C Runtime 更新）；
- 远程控制要求设备允许 `adb shell` 以 shell 身份启动 `app_process`（部分深度定制的 TV ROM 会限制）；不满足时会自动回退到 `adb screenrecord`，功能仍可用但流畅度会下降。

## 连接准备

[观看视频](/docs/videos/1.mp4)

### 开启开发者模式

`设置 - 关于 - 版本号`，连续点击 `7 次` 开启开发者模式。

### 安卓 11 及以上

`设置 - 系统 - 开发者选项`，找到 `无线调试`，连接 WiFi 后开启，进入 `无线调试` 查看 `IP 地址和端口`，使用该地址即可无线连接。

> 注：部分设备入口位置不同，请自行寻找。

### 安卓 11 以下

连接 WiFi 后查看设备 `局域网 IP 地址`，使用该地址即可无线连接，此时无需输入端口号。

> 注：过低版本的设备可能无法连接。

## 安装和使用

提供自包含的单文件安装程序 `AdbToolsInstaller.exe`，具备以下特性：

- **单个 exe 直接安装**，无需先解压；
- 在「程序和功能」中始终保持**唯一条目**，不同版本不会重复出现；
- 升级时自动读取上次安装位置并**覆盖到原目录**；
- 在桌面与开始菜单创建名为 **`Adb连接工具`** 的快捷方式；
- 通过安装目录下的 `uninstall.exe`（或「程序和功能」）即可**干净卸载**。

安装包内含文件（安装后位于程序目录）：

| 文件 | 用途 |
| --- | --- |
| `AdbTools.exe`、`QRCoder.dll` | 主程序与扫码配对 |
| `Hardcodet.NotifyIcon.Wpf.dll` | 系统托盘图标与通知气泡 |
| `adb.exe`、`AdbWinApi.dll`、`AdbWinUsbApi.dll` | ADB 及 USB 依赖 |
| `libwebp.dll` | 应用图标 WebP 解码 |
| `System.Data.SQLite.dll`、`SQLite.Interop.dll` | 应用名 / 图标 / 系统服务缓存数据库 |
| `scrcpy-server` | 远程控制的设备端取流服务（运行时推送到设备 `/data/local/tmp/`） |
| `scrcpy-LICENSE.txt`、`THIRD_PARTY_NOTICES.txt` | 第三方许可证全文与许可/组件声明 |
| `LICENSE.txt` | 本项目 Apache-2.0 许可证全文（含版权声明） |
| `uninstall.exe` | 卸载程序 |

安装时会额外写入 `install.manifest` 记录本次释放的文件清单，卸载时按清单精确删除，不会误删目录内的其他文件。

重新生成安装包：在 Visual Studio 中直接生成 `AdbToolsInstaller` 项目（会自动编译主程序与卸载器、打包并嵌入 payload）。脚本 `build_payload.ps1` 会收集主程序输出目录下的全部 `*.exe` / `*.dll`（含 `libwebp.dll`、`SQLite.Interop.dll`）、运行配置 `AdbTools.exe.config`，以及上表中的非程序文件一并纳入 `payload.zip`。

### 软件更新

- 顶部「关于 → 检查更新」会从 Gitea 仓库镜像读取最新版本号与安装程序；
- 确认更新后，安装包下载到 `%APPDATA%\AdbTools\cache`（与其它临时文件统一管理，不占用 `%TEMP%`），下载完成自动启动安装程序并退出本程序；
- 覆盖安装会保留 `%APPDATA%\AdbTools\AdbTools.config` 中的配置与连接历史；
- 每次启动会清空 `cache` 目录，残留安装包不会累积；
- 下载目录位于当前用户目录，无需管理员权限；安装程序覆盖程序目录时按系统提示授权即可。

## 使用说明

### 设备配对（Android 11+）

配对窗口顶部提供「扫码配对 / 配对码」切换条，**默认进入扫码配对**。

**方式一：扫码配对（推荐，默认）**

1. 点击「配对 (`F8`)」打开配对窗口（默认即为扫码界面）；
2. 工具生成配对二维码（协议与 Android Studio 一致），上方高亮条提示手机操作路径；
3. 手机在「无线调试 - 使用二维码配对设备」界面扫描二维码，工具自动发现设备并完成配对；配对成功后配对窗口**直接关闭**（不弹提示），后台自动尝试连接（最多 3 次，无需等待），是否连上以设备列表为准。

> 注：部分老设备 ADB Wi-Fi 版本较低（v1.0）配对能力受限，扫码失败时请改用方式二。

**方式二：输入配对码**

1. 在配对窗口点击「配对码」切换到手动模式；
2. 在设备「无线调试 - 使用配对码配对设备」中获取 `IP:端口` 与配对码；
3. 输入**配对地址**与**配对码**，点击「配对 (`Enter`)」或按回车完成。

### 设备连接

1. 在「IP 和端口」输入框中输入设备的 `IP:端口`（可省略端口，默认 `5555`）；
2. 点击「连接 (`Enter`)」或按回车，等待连接成功。

### 历史记录

- 连接成功的地址会保存在下拉历史中；
- 展开输入框右侧下拉，右键某条记录可进行「删除记录 / 清空所有记录」。

### 设备列表操作

右键已连接设备，可进行的操作：

| 菜单 | 说明 |
| --- | --- |
| 安装应用 | 选择 APK 文件安装到该设备，确认窗口显示应用名与包名（支持 `.apk` 与 `.apk.1` 等改名文件） |
| 远程控制 | 打开实时画面与输入控制窗口（详见[远程控制](#远程控制)） |
| 文件管理 | 浏览设备文件，支持上传 / 下载文件与文件夹（详见[文件管理](#文件管理)） |
| 断开设备 | 断开当前设备 |
| 查看日志 - 实时日志 / Debug 日志 | 打开独立日志窗口，支持缓冲切换、级别 / 关键字过滤、暂停、清空、保存与选择复制 |
| 查看日志 - 抓取崩溃日志 | 导出 crash 缓冲区到 `%APPDATA%\AdbTools\DeviceLogs\<设备名称>\` |

### 应用列表

右键设备 →「应用控制 → 应用列表」。列表以**独立窗口**打开，不依附主界面，可单独最小化或拖到另一块屏幕；同一台手机只保留一个窗口，重复点击会把已打开的窗口带到前台。

包名与状态来自设备端命令，但**应用名需要额外拉取数据**：

- **包名与状态**：`pm list packages -f` 取包名与 APK 路径，`-s` / `-d` 标记系统应用与已停用应用，`-u` 用于发现已从手机上移除的系统应用，返回很快。
- **应用名**：Android 没有直接查询应用名的命令，只能读取每个应用 APK 内的 `AndroidManifest.xml` 与 `resources.arsc`，在本机解析 `android:label`，并优先取简体中文资源。
- **系统服务**：解析 manifest，把系统应用里「无桌面入口」或「声明常驻（persistent）」的应用标记为「系统服务」，列表以橙色标签显示并支持筛选。
- **图标**：与名称一起解析，取 APK 里最高密度的图标位图；自适应图标（`mipmap-anydpi-v26/*.xml`）会再读它的前景层；WebP 与矢量图（VectorDrawable）图标由本机解码 / 渲染后缓存。解析不到图标的少数应用显示「包名首字 + 固定色块」占位，取到图标后色块自动隐藏（透明背景的图标不会透出底色），不影响其它信息。
- **拉取量**：每个应用只取 manifest、资源表和一张图标（多数几十 KB 到几百 KB，**不下载整个 APK**）。325 个应用首次约需 1~2 分钟，状态栏显示进度；可随时点「停止获取名称」中断，关闭窗口也会立即停止。
- **大应用较慢**：资源表特别大的应用（例如系统「设置」约 104MB）单个约需 1 分钟；超过 160MB 的直接跳过，只显示包名。
- **缓存按设备隔离**：名称、系统服务标记、解析状态与图标都存在 `%APPDATA%\AdbTools\data\AdbTools.db`（SQLite），并按设备键分开。同一个包在不同手机上名称/图标不同时各自保存，互不覆盖；来自缓存的行会在列表中以「缓存」标签标注。
- **图标去重**：图标内容按 SHA1 存一份，多个应用共用同一张图（或同一应用在多台设备上图标相同）只占一份空间；无人引用的图标会在下次打开列表时清理。
- **远程控制窗口尺寸**：手动调整过的窗口**大小**按设备保存在同一个库（横屏、竖屏各一份），下次打开同一台手机直接沿用；不记位置，恢复时按屏幕居中并把尺寸限制在工作区内，不会跑到屏幕外。
- **设备键**：依次取 `ro.serialno` → `ro.boot.serialno` → `android_id`，都由设备自身返回，同一台手机用 USB / IP / 无线调试连接时结果相同，因此多种连接方式共用一份缓存；三者都取不到时才退回连接序列号（此时各连接方式会各存一份）。硬件序列号在设备列表刷新时与品牌型号一并读取，打开应用列表、远程控制时直接使用，不再额外发命令。
- **库结构**：当前为 v2（v2 相比 v1 只新增远程控制窗口尺寸表），升级时原有缓存不受影响。
- **仍显示包名的情况**：少数系统包（如部分 apex 虚拟化组件）本身没有 `android:label`，只能显示包名。
- **不影响操作**：名称只用于显示，卸载 / 停用 / 启用 / 清除数据等功能随时可用，不必等名称解析完成。
- **WiFi 调试注意**：数据经 adb 通道传输，WiFi 下会占用带宽；解析期间同时使用远程控制可能互相影响，可先点「停止获取名称」。

### 文件管理

右键设备 →「文件管理」（托盘菜单同样有入口），以独立窗口浏览设备文件，同一台设备只保留一个窗口。

- **浏览**：默认打开 `/sdcard`；顶部路径栏可直接输入路径回车跳转，双击文件夹进入；工具栏「上级」或 `Backspace` 返回上一级，`F5` 刷新。
- **符号链接**：列表里类型显示为「链接」，双击时先解析目标——指向目录就进入，指向文件则按文件下载（例如 `/sdcard` 本身就指向 `/storage/self/primary`）。
- **上传**：「上传文件」可一次选多个文件，「上传文件夹」上传整个目录，目标都是当前目录；`adb push` 原生支持目录递归，子目录结构会保留。
- **下载**：选中一项或多项（`Ctrl` / `Shift` 多选）后点「下载」，再选择本地目录；下载文件夹同样保留子目录结构（会在目标目录下创建同名文件夹）。
- **新建 / 重命名 / 删除**：工具栏对应按钮，`Delete` 键删除选中项；**删除不可恢复**，会二次确认并列出待删项目。
- **传输状态**：状态栏显示「上传中 2/5：文件名」，可点「取消传输」中断；失败项会汇总提示（最多列出 10 项），取消后设备端可能残留半个文件。
- **权限**：`/sdcard`、`/sdcard/Download`、`/sdcard/DCIM` 等可直接读写；`/data/data`、`/data/system` 是应用私有数据，普通 shell 无权限；`/system`、`/vendor` 只读，写入会提示分区只读。
- **提示位置**：无权限、目录不存在、空目录等结果会**直接显示在列表区域中央**（含路径、原因与处理建议），并提供「返回上级 / 刷新」按钮。
- **注意**：WiFi 连接下大批量传输会占用带宽，同时使用远程控制会掉帧；传输过程中关闭窗口会先确认再取消。

### 卸载与恢复

- **系统应用**：卸载走 `pm uninstall --user 0`，只是从当前用户下移除，**系统分区里的安装文件不会被删除**。刷新列表后，可在筛选「已卸载应用」里找到它，点「恢复」用 `pm install-existing` 装回来，不需要重新下载 APK；但账号与登录状态已被清除。若只想暂时隐藏并保留数据，应改用「停用」。
- **第三方应用**：卸载是完整卸载，APK 与数据一并删除，不可撤销，也不会出现在「已卸载应用」里。
- **恢复的前提**：安装文件仍在系统分区（`/system`、`/system_ext`、`/product`、`/vendor`、`/odm`、`/apex`）。极少数被厂商 OTA 精简掉的组件、或系统版本过低没有 `install-existing` 命令的设备，恢复会失败并给出具体原因提示。
- **已卸载行的显示**：状态标签为「已卸载」，「卸载」按钮隐藏，主操作按钮变为「恢复」。

### 操作日志

点击菜单「查看日志」或右键设备的日志项，弹出「操作日志」窗口，记录每次操作的结果与状态；右键日志可「复制命令」便于排查。

### 设备日志窗口

右键设备 →「查看日志 → 实时日志」打开独立日志窗口：

- **级别**：全部级别 / Debug 及以上 / Info 及以上 / Warn 及以上 / Error 及以上，按 logcat 级别字段过滤。
- **过滤**：按关键字筛选（不区分大小写），修改后自动从最近 20000 行重建视图。
- **暂停 / 继续**：暂停后仍继续接收，只冻结显示。
- **清空**：清空当前显示，并同步清空设备端对应缓冲区（有确认提示）。
- **保存**：导出当前显示内容到 `%APPDATA%\AdbTools\DeviceLogs\<设备名称>\`。

  - 单击选中一行，`Shift + 单击` 连续多选，`Ctrl + 单击` 点选多行；

  - `Ctrl + A` 全选。
- **颜色**：按 Android Studio logcat 配色区分级别——V 灰、D 蓝、I 绿、W 橙、E 红、F/A 紫；`[adb]` 错误输出为红色。
- **抓取崩溃日志 / 诊断包**：「查看日志」菜单中，诊断包包含 logcat、crash、dropbox、内存 / CPU 与设备信息，打包为 zip。
- 显示上限 5000 行，超出后自动丢弃最早的行；关闭窗口时会结束对应的 adb 进程。

## 远程控制

右键已连接设备 →「**远程控制**」打开实时画面窗口；多台设备可各自独立开窗口，互不影响。

### 窗口布局

- **顶部**：左侧状态栏只显示 `画面分辨率 → 设备物理分辨率   上屏帧率`；右侧是 **1:1 按钮**与清晰度下拉框（每项带图标，悬停可查看清晰度 / 速度 / 建议说明）。点「1:1」会把窗口调整到当前输出画面的像素尺寸，画面 1 像素对应屏幕 1 像素（高 DPI 下按实际缩放换算）；屏幕放不下时自动缩小并提示实际比例，达到 1:1 时也会提示。
- **中部**：实时画面，横竖屏切换时窗口按新比例自动调整并重新居中；**手动调整过窗口大小后不再自动改尺寸**，横屏与竖屏各记住一份**大小**并按设备保存，下次打开同一台手机直接沿用（恢复时居中且不超出屏幕），切换清晰度也不影响；首帧前与设备息屏时会在画面中央显示同款状态卡片。
- **底部**：返回 / Home / 任务 / 音量 / 电源 虚拟按键。音量键**按住持续调大 / 调小**（松开即停，不限次数）；电源键按住 **< 0.5 秒**为短按（亮屏 / 灭屏），**≥ 0.5 秒**松开时按长按处理（注入 `--longpress`）。
- **输入**：点击、拖拽与虚拟按键走 scrcpy 控制通道，按下即注入、拖动时逐条发送移动事件，延迟为毫秒级；控制通道不可用时自动回退 `adb shell input`，此时拖拽改为松手后一次性滑动。
- **滚轮**：在画面上滚动会转换为一次短距离滑动，抬手后由系统产生惯性；连续滚动会合并成一次手势，避免命令排队。

### 清晰度档位

| 档位 | 长边 | 特点 | 建议场景 |
| --- | --- | --- | --- |
| 原画 | 不缩放 | 最清晰，编解码与带宽开销最高 | USB、需要看清细节或截图取材 |
| 1080P 超清 | 1920 | 清晰度很高，开销约为原画的一半 | USB 或 5G Wi-Fi，兼顾清晰与流畅 |
| 720P 高清 | 1280 | 清晰够用，开销约为原画的 1/4 | 2.4G Wi-Fi、低配电脑、设备性能较弱 |
| 480P 标清 | 854 | 偏糊，小字可能看不清 | 网络较差、只需点击操作和看大致画面 |
| 360P 流畅 | 640 | 最低开销，只能看清大块内容与图标 | 网络差、设备性能弱，或只操作界面 |

程序会按设备原生分辨率**自动隐藏根本达不到的高档位**（例如 720P 屏不会列出 1080P）；若某档位的编码器不兼容，会**逐级向下实际验证**并移除失败档位，直到找到能正常出画面的档位。设备完全不支持 scrcpy server 时自动回退 `adb screenrecord`。

### 状态与指标

- 状态栏帧率统计的是**真正写进画面的帧数**（不是解码输出数），并按真实经过时间计算；悬停可查看上屏 / 解码帧率与上屏延迟的说明。画面静止时设备端不产帧，显示 `0 fps` 属正常现象。
- 锁屏但屏幕仍亮时继续取流，方便在锁屏界面上滑动解锁；息屏时画面中央提示「设备已息屏」。
- 启动过程与息屏提示以中央卡片告知；关闭窗口时窗口**立即消失**，停止取流、清理设备端服务与 adb 转发全部转到后台完成，主界面不会卡顿。同一台设备只保留一个远程控制窗口，重复打开会把已有窗口还原到前台。

## 常见问题

- **连接失败**：确认设备与电脑在同一局域网，开发者选项与无线调试已开启，且 IP/端口正确。
- **无法识别设备**：Android 11+ 需先完成配对再连接；旧版本系统可能不支持无线连接。
- **配对窗口自动关闭**：配对成功时配对窗口会**直接关闭且不弹提示**，属正常现象；此时后台会自动尝试连接（最多 3 次）并刷新列表，**能否连上以设备列表为准**——若列表中未出现该设备，请稍后点击「刷新 (`F5`)」或重新「连接」；如需重新配对，再次点击「配对 (`F8`)」即可。若窗口未关闭并给出提示，则说明配对失败，按提示检查地址、配对码或网络。
- **程序无法启动**：请确认已安装 `.NET Framework 4.6.2` 运行时（Win10 早期版本与 Win7/8.1 需自行安装）。
- **找不到程序入口**：安装完成后，可从桌面或开始菜单的 **`Adb连接工具`** 快捷方式启动。
- **文件管理里 `/data/data` 打不开**：这是系统保护的应用私有目录，普通 shell 用户没有权限；调试版本应用可用 `run-as <包名>` 访问（本工具暂未提供），需要完整访问请使用已 root 的设备。
- **文件管理下载文件夹后多了一层同名目录**：下载文件夹时会在选定目录下创建同名文件夹并放入内容，这是保留原目录结构的预期行为。
- **远程控制画面几秒才变一次**：静止界面设备端本来就不产帧（帧率会显示 `0 fps`）；若播放视频时画面区域仍是黑的，通常是 DRM 安全图层，软件层无法捕获，只能改用 HDMI 采集卡。可先切到「设置」等持续动画的纯 UI 页确认。
- **TV 机顶盒远程控制不流畅**：优先手动切到 720P、480P 或 360P；程序也会在编码器不兼容时自动逐级降档。若日志提示「回退到 screenrecord」，说明该 ROM 限制了 `app_process`，属兼容兜底。
- **清晰度下拉里少了几个档位**：设备原生分辨率达不到的档位会在启动时隐藏，验证失败的档位会被移除，属正常行为。
- **远程控制提示「系统缺少媒体组件」**：当前系统未包含 Media Foundation（常见于 Windows N / KN 版或精简系统），安装系统对应的「媒体功能包」后即可正常取流；与设备连接无关，不必反复检查数据线或网络。
- **帧率正常但操作有粘滞感**：状态栏显示的是真实上屏帧率；粘滞主要来自设备端采集编码与 adb 往返（约 100~200 ms），切到更低的分辨率档位可缓解。
- **关闭远程控制窗口后设备端还残留一会儿服务**：关闭时窗口立即消失，停止取流与清理设备端服务、adb 转发在后台进行（通常 1~3 秒），期间设备端服务可能短暂残留，属正常现象。
- **点了 × 程序没有退出**：程序默认收起到系统托盘继续后台运行，右键托盘图标选择「退出」才会真正退出；也可在「设置 → 关闭方式」里选「直接退出程序」。
- **日志在哪里**：远程控制日志 `%APPDATA%\AdbTools\logs\RemoteControl-yyyyMMdd.log`、应用列表日志 `%APPDATA%\AdbTools\logs\AppList-yyyyMMdd.log`（按天分文件，自动保留 7 天）；抓取的设备日志与诊断包位于 `%APPDATA%\AdbTools\DeviceLogs\<设备名称>\`；配置与设备历史位于 `%APPDATA%\AdbTools\AdbTools.config`；应用数据（应用名与图标缓存）位于 `%APPDATA%\AdbTools\data\AdbTools.db`；所有临时文件统一放在 `%APPDATA%\AdbTools\cache`，每次启动自动清空，不会写到系统临时目录。
