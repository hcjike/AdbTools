# AdbTools

一款基于 WPF（C#）开发的 Windows 桌面工具，封装 ADB（Android Debug Bridge）常用命令，提供图形化界面实现 Android 设备的**无线连接、配对、设备管理、应用调试与实时远程控制**，无需记忆命令行。内置 `adb.exe`、远程控制所需的 scrcpy 设备端组件及依赖，开箱即用。

## 功能特性

- **无线连接**：输入 `IP:端口` 即可无线连接设备，支持省略端口（默认 `5555`）。
- **无线配对**：配对窗口内置「扫码配对 / 配对码」切换条（默认扫码）。扫码配对由工具生成二维码（协议同 Android Studio），手机端「使用二维码配对设备」扫码后自动完成配对、连接在后台静默尝试；也可切到「配对码」手动输入 `IP:端口` 与配对码配对。配对成功后直接关闭配对窗口，无需等待连接。
- **连接管理**：设备列表展示、一键刷新（`F5`）、**定时刷新**（关闭 / 3 秒 / 5 秒 / 10 秒 / 15 秒 / 20 秒 / 30 秒 / 60 秒，设置自动保存）、断开单个 / 断开所有设备；设备名称读取完成前显示 `unknown`，读取后自动刷新。
- **历史记录**：自动保存成功连接的地址，下拉框可右键「删除记录 / 清空所有记录」。
- **应用安装**：右键设备行「安装应用」选择 APK，或直接把 APK 文件**拖拽**到设备行安装。
- **应用控制**：打开应用列表查看全部应用（应用名 / 包名 / 系统或第三方 / 停用状态），支持搜索与筛选，可直接卸载、停用/启用、清除缓存或数据。
- **设备调试**：打开 Shell 窗口、独立日志窗口（缓冲切换、级别 / 关键字过滤、暂停、清空、保存、选择复制）、一键抓取崩溃日志与诊断包、恢复默认 TCP 端口 / 分辨率 / DPI。
- **实时远程控制**：右键设备行即可打开实时画面窗口，支持触摸 / 滑动与返回、Home、任务、音量、电源等虚拟按键；设备端用 MediaCodec 主动编码（scrcpy server）输出 H.264，画面横竖屏自动适配。内置五档采集分辨率（原画 / 1080P / 720P / 480P / 360P），带清晰度图标与悬停说明；设备达不到的档位自动隐藏，编码器不兼容时**逐级向下验证**直到找到可用档位，最后仍不可用时自动回退 `adb screenrecord`。状态栏显示真实上屏帧率，启动、息屏与关闭过程在画面中央给出卡片提示。
- **操作日志**：独立日志窗口记录操作过程与状态，可右键复制命令。
- **其它**：窗口置顶、最小化、关于信息、项目地址（含镜像）、检查更新（Gitea 仓库镜像）。

## 开发环境

- 开发工具：Visual Studio 2019 / 2022
- 框架：`.NET Framework 4.6`
- 平台：`x64`

## 运行环境

- 需要 `.NET Framework 4.6` 运行时；
- `64 位 Windows` 系统；
- 程序已内置 `adb.exe` 及依赖（`AdbWinApi.dll`、`AdbWinUsbApi.dll`、`QRCoder.dll`）、远程控制所需的 `scrcpy-server` 与授权文件（`scrcpy-LICENSE.txt`、`THIRD_PARTY_NOTICES.txt`），以及本项目许可证 `LICENSE.txt`，**无需电脑另行安装 ADB、scrcpy 或 VC++ 运行库**，Windows 10/11 开箱即用。adb 命令会自动拉起自带服务，不依赖系统中已存在的 adb 服务（Win7/8/8.1 需系统已安装 Universal C Runtime 更新）；
- 远程控制要求设备允许 `adb shell` 以 shell 身份启动 `app_process`（部分深度定制的 TV ROM 会限制）；不满足时会自动回退到 `adb screenrecord`，功能仍可用但流畅度会下降。

## 连接准备

[观看视频](/docs/videos/1.mp4)

### 开启开发者模式

`设置 - 关于 - 版本号`，连续点击 `7 次` 开启开发者模式。

### 安卓 11 及以上

`设置 - 系统 - 开发者选项`，找到 `无线调试`，连接 WiFi 后开启，进入 `无线调试` 查看 `IP 地址和端口`，使用该地址即可无线连接。

> 注：部分设备入口位置不同，请自行寻找。

### 安卓 11 以下

连接 WiFi 后查看设备 `局域网 IP 地址`，使用该地址即可无线连接，此时无需输入端口号。

> 注：过低版本的设备可能无法连接。

## 安装和使用

提供自包含的单文件安装程序 `AdbToolsInstaller.exe`，具备以下特性：

- **单个 exe 直接安装**，无需先解压；
- 在「程序和功能」中始终保持**唯一条目**，不同版本不会重复出现；
- 升级时自动读取上次安装位置并**覆盖到原目录**；
- 在桌面与开始菜单创建名为 **`Adb连接工具`** 的快捷方式；
- 通过安装目录下的 `uninstall.exe`（或「程序和功能」）即可**干净卸载**。

安装包内含文件（安装后位于程序目录）：

| 文件 | 用途 |
| --- | --- |
| `AdbTools.exe`、`QRCoder.dll` | 主程序与扫码配对 |
| `adb.exe`、`AdbWinApi.dll`、`AdbWinUsbApi.dll` | ADB 及 USB 依赖 |
| `scrcpy-server` | 远程控制的设备端取流服务（运行时推送到设备 `/data/local/tmp/`） |
| `scrcpy-LICENSE.txt`、`THIRD_PARTY_NOTICES.txt` | 第三方许可证全文与许可/组件声明 |
| `LICENSE.txt` | 本项目 Apache-2.0 许可证全文（含版权声明） |
| `uninstall.exe` | 卸载程序 |

安装时会额外写入 `install.manifest` 记录本次释放的文件清单，卸载时按清单精确删除，不会误删目录内的其他文件。

重新生成安装包：在 Visual Studio 中直接生成 `AdbToolsInstaller` 项目（会自动编译主程序与卸载器、打包并嵌入 payload）。脚本 `build_payload.ps1` 会把上述非 exe/dll 的随包文件一并纳入 `payload.zip`。

### 软件更新

- 顶部「关于 → 检查更新」会从 Gitea 仓库镜像读取最新版本号与安装程序；
- 确认更新后，安装包下载到 `%APPDATA%\AdbTools\cache`（与其它临时文件统一管理，不占用 `%TEMP%`），下载完成自动启动安装程序并退出本程序；
- 覆盖安装会保留 `%APPDATA%\AdbTools\AdbTools.config` 中的配置与连接历史；
- 每次启动会清空 `cache` 目录，残留安装包不会累积；
- 下载目录位于当前用户目录，无需管理员权限；安装程序覆盖程序目录时按系统提示授权即可。

## 使用说明

### 设备配对（Android 11+）

配对窗口顶部提供「扫码配对 / 配对码」切换条，**默认进入扫码配对**。

**方式一：扫码配对（推荐，默认）**

1. 点击「配对 (`F8`)」打开配对窗口（默认即为扫码界面）；
2. 工具生成配对二维码（协议与 Android Studio 一致），上方高亮条提示手机操作路径；
3. 手机在「无线调试 - 使用二维码配对设备」界面扫描二维码，工具自动发现设备并完成配对；配对成功后配对窗口**直接关闭**（不弹提示），后台自动尝试连接（最多 3 次，无需等待），是否连上以设备列表为准。

> 注：部分老设备 ADB Wi-Fi 版本较低（v1.0）配对能力受限，扫码失败时请改用方式二。

**方式二：输入配对码**

1. 在配对窗口点击「配对码」切换到手动模式；
2. 在设备「无线调试 - 使用配对码配对设备」中获取 `IP:端口` 与配对码；
3. 输入**配对地址**与**配对码**，点击「配对 (`Enter`)」或按回车完成。

### 设备连接

1. 在「IP 和端口」输入框中输入设备的 `IP:端口`（可省略端口，默认 `5555`）；
2. 点击「连接 (`Enter`)」或按回车，等待连接成功。

### 历史记录

- 连接成功的地址会保存在下拉历史中；
- 展开输入框右侧下拉，右键某条记录可进行「删除记录 / 清空所有记录」。

### 设备列表操作

右键已连接设备，可进行的操作：

| 菜单 | 说明 |
| --- | --- |
| 安装应用 | 选择 APK 文件安装到该设备 |
| 远程控制 | 打开实时画面与输入控制窗口（详见[远程控制](#远程控制)） |
| 断开设备 | 断开当前设备 |
| 查看日志 - 实时日志 / Debug 日志 | 打开独立日志窗口，支持缓冲切换、级别 / 关键字过滤、暂停、清空、保存与选择复制 |
| 查看日志 - 抓取崩溃日志 | 导出 crash 缓冲区到 `%APPDATA%\AdbTools\DeviceLogs\<设备名称>\` |
| 查看日志 - 抓取诊断包 | 打包 logcat、crash、dropbox、内存 / CPU 与设备信息为 zip |
| 查看日志 - 打开日志目录 | 打开当前设备的日志文件夹 |
| 恢复默认 - TCP 端口 / 分辨率 / DPI | 还原设备默认设置 |
| 应用控制 - Shell 窗口 | 打开命令行 Shell |
| 应用控制 - 应用列表 | 查看全部应用，支持搜索、筛选、卸载、停用 / 启用、清除缓存 / 数据 |
| 应用控制 - 指定包名 | 启用 / 禁用指定应用 |
| 断开所有设备 | 断开全部连接 |

> 也可将 APK 文件直接拖拽到设备行进行安装。

### 应用列表

右键设备 →「应用控制 → 应用列表」。包名与状态来自设备端命令，但**应用名需要额外拉取数据**：

- **包名与状态**：`pm list packages -f` 取包名与 APK 路径，`-s` / `-d` 标记系统应用与已停用应用，返回很快。
- **应用名**：Android 没有直接查询应用名的命令，只能读取每个应用 APK 内的 `AndroidManifest.xml` 与 `resources.arsc`，在本机解析 `android:label`，并优先取简体中文资源。
- **拉取量**：每个应用只取上面两个文件（多数几十 KB 到几百 KB，**不下载整个 APK**）。325 个应用首次约需 1~2 分钟，状态栏显示进度；可随时点「停止获取名称」中断，关闭窗口也会立即停止。
- **大应用较慢**：资源表特别大的应用（例如系统「设置」约 104MB）单个约需 1 分钟；超过 160MB 的直接跳过，只显示包名。
- **缓存**：解析结果保存在 `%APPDATA%\AdbTools\data\app.db`（SQLite），第二次打开直接命中，不再拉取。
- **仍显示包名的情况**：少数系统包（如部分 apex 虚拟化组件）本身没有 `android:label`，只能显示包名。
- **不影响操作**：名称只用于显示，卸载 / 停用 / 启用 / 清除缓存等功能随时可用，不必等名称解析完成。
- **WiFi 调试注意**：数据经 adb 通道传输，WiFi 下会占用带宽；解析期间同时使用远程控制可能互相影响，可先点「停止获取名称」。

### 操作日志

点击菜单「查看日志」或右键设备的日志项，弹出「操作日志」窗口，记录每次操作的结果与状态；右键日志可「复制命令」便于排查。

### 设备日志窗口

右键设备 →「查看日志 → 实时日志」打开独立日志窗口：

- **缓冲**：main 主日志 / system 系统 / crash 崩溃 / events 事件 / 全部缓冲；鼠标悬停每一项可查看该缓冲的用途说明。
- **级别**：全部级别 / Debug 及以上 / Info 及以上 / Warn 及以上 / Error 及以上，按 logcat 级别字段过滤。
- **过滤**：按关键字筛选（不区分大小写），修改后自动从最近 20000 行重建视图。
- **暂停 / 继续**：暂停后仍继续接收，只冻结显示。
- **清空**：清空当前显示，并同步清空设备端对应缓冲区（有确认提示）。
- **保存**：导出当前显示内容到 `%APPDATA%\AdbTools\DeviceLogs\<设备名称>\`。
- **选择与复制**：
  - 单击选中一行，`Shift + 单击` 连续多选，`Ctrl + 单击` 点选多行；
  - `Ctrl + C` 复制选中行（未选中时复制当前显示的全部），按显示顺序输出；
  - `Ctrl + A` 全选。
- **颜色**：按 Android Studio logcat 配色区分级别——V 灰、D 蓝、I 绿、W 橙、E 红、F/A 紫；`[adb]` 错误输出为红色。
- **抓取崩溃日志 / 诊断包**：「查看日志」菜单中，诊断包包含 logcat、crash、dropbox、内存 / CPU 与设备信息，打包为 zip。
- 显示上限 5000 行，超出后自动丢弃最早的行；关闭窗口时会结束对应的 adb 进程。

### 设置与关于

- **设置**：
  - **置顶显示**：以对号表示是否开启，点击切换窗口是否始终在最前；
  - **定时刷新**：鼠标悬停「定时刷新」即在右侧展开间隔选项（关闭 / 3 秒 / 5 秒 / 10 秒 / 15 秒 / 20 秒 / 30 秒 / 60 秒），选择后自动保存并在下次启动沿用；定时刷新在后台静默执行，不显示加载动画。
- **关于**：
  - **项目地址**：GitHub 主页（源码浏览）；
  - **项目地址（镜像）**：Gitea 仓库（`code.hcjike.com`）；
  - **检查更新**：从 Gitea 仓库的 Releases 拉取最新版本信息与安装包，发现新版本时提示更新；安装包下载到 `%APPDATA%\AdbTools\cache`，安装后下次启动自动清理。

## 远程控制

右键已连接设备 →「**远程控制**」打开实时画面窗口；多台设备可各自独立开窗口，互不影响。

### 窗口布局

- **顶部**：左侧状态栏只显示 `画面分辨率 → 设备物理分辨率   上屏帧率`；右侧是清晰度下拉框，每项带图标，悬停可查看清晰度 / 速度 / 建议说明。
- **中部**：实时画面，横竖屏切换时窗口按新比例自动调整并重新居中；首帧前、设备息屏、关闭过程中会在画面中央显示同款状态卡片。
- **底部**：返回 / Home / 任务 / 音量 / 电源 虚拟按键。音量键**按住持续调大 / 调小**（松开即停，不限次数）；电源键按住 **< 0.5 秒**为短按（亮屏 / 灭屏），**≥ 0.5 秒**松开时按长按处理（注入 `--longpress`）。
- **输入**：点击、拖拽与虚拟按键走 scrcpy 控制通道，按下即注入、拖动时逐条发送移动事件，延迟为毫秒级；控制通道不可用时自动回退 `adb shell input`，此时拖拽改为松手后一次性滑动。
- **滚轮**：在画面上滚动会转换为一次短距离滑动，抬手后由系统产生惯性；连续滚动会合并成一次手势，避免命令排队。

### 清晰度档位

| 档位 | 长边 | 特点 | 建议场景 |
| --- | --- | --- | --- |
| 原画 | 不缩放 | 最清晰，编解码与带宽开销最高 | USB、需要看清细节或截图取材 |
| 1080P 超清 | 1920 | 清晰度很高，开销约为原画的一半 | USB 或 5G Wi-Fi，兼顾清晰与流畅 |
| 720P 高清 | 1280 | 清晰够用，开销约为原画的 1/4 | 2.4G Wi-Fi、低配电脑、设备性能较弱 |
| 480P 标清 | 854 | 偏糊，小字可能看不清 | 网络较差、只需点击操作和看大致画面 |
| 360P 流畅 | 640 | 最低开销，只能看清大块内容与图标 | 网络差、设备性能弱，或只操作界面 |

程序会按设备原生分辨率**自动隐藏根本达不到的高档位**（例如 720P 屏不会列出 1080P）；若某档位的编码器不兼容，会**逐级向下实际验证**并移除失败档位，直到找到能正常出画面的档位。设备完全不支持 scrcpy server 时自动回退 `adb screenrecord`。

### 状态与指标

- 状态栏帧率统计的是**真正写进画面的帧数**（不是解码输出数），并按真实经过时间计算；悬停可查看上屏 / 解码帧率与上屏延迟的说明。画面静止时设备端不产帧，显示 `0 fps` 属正常现象。
- 锁屏但屏幕仍亮时继续取流，方便在锁屏界面上滑动解锁；息屏时画面中央提示「设备已息屏」。
- 启动过程、息屏提示、关闭清理都以中央卡片告知；关闭时会等后台停止取流、清理设备端服务与转发完成后才真正关掉窗口，主界面不会卡顿。

## 常见问题

- **连接失败**：确认设备与电脑在同一局域网，开发者选项与无线调试已开启，且 IP/端口正确。
- **无法识别设备**：Android 11+ 需先完成配对再连接；旧版本系统可能不支持无线连接。
- **配对窗口自动关闭**：配对成功时配对窗口会**直接关闭且不弹提示**，属正常现象；此时后台会自动尝试连接（最多 3 次）并刷新列表，**能否连上以设备列表为准**——若列表中未出现该设备，请稍后点击「刷新 (`F5`)」或重新「连接」；如需重新配对，再次点击「配对 (`F8`)」即可。若窗口未关闭并给出提示，则说明配对失败，按提示检查地址、配对码或网络。
- **程序无法启动**：请确认已安装 `.NET Framework 4.6` 运行时。
- **找不到程序入口**：安装完成后，可从桌面或开始菜单的 **`Adb连接工具`** 快捷方式启动。
- **远程控制画面几秒才变一次**：静止界面设备端本来就不产帧（帧率会显示 `0 fps`）；若播放视频时画面区域仍是黑的，通常是 DRM 安全图层，软件层无法捕获，只能改用 HDMI 采集卡。可先切到「设置」等持续动画的纯 UI 页确认。
- **TV 机顶盒远程控制不流畅**：优先手动切到 720P、480P 或 360P；程序也会在编码器不兼容时自动逐级降档。若日志提示「回退到 screenrecord」，说明该 ROM 限制了 `app_process`，属兼容兜底。
- **清晰度下拉里少了几个档位**：设备原生分辨率达不到的档位会在启动时隐藏，验证失败的档位会被移除，属正常行为。
- **帧率正常但操作有粘滞感**：状态栏显示的是真实上屏帧率；粘滞主要来自设备端采集编码与 adb 往返（约 100~200 ms），切到更低的分辨率档位可缓解。
- **关闭窗口时停在「正在关闭…」**：正在后台停止取流、清理设备端服务与转发，完成后窗口会自动关闭；这是为了避免清理阻塞 UI 线程导致主界面卡顿。
- **日志在哪里**：远程控制日志 `%APPDATA%\AdbTools\logs\RemoteControl-yyyyMMdd.log`、应用列表日志 `%APPDATA%\AdbTools\logs\AppList-yyyyMMdd.log`（按天分文件，自动保留 7 天）；抓取的设备日志与诊断包位于 `%APPDATA%\AdbTools\DeviceLogs\<设备名称>\`；配置与设备历史位于 `%APPDATA%\AdbTools\AdbTools.config`；应用数据（应用名缓存）位于 `%APPDATA%\AdbTools\data\app.db`；所有临时文件统一放在 `%APPDATA%\AdbTools\cache`，每次启动自动清空，不会写到系统临时目录。
