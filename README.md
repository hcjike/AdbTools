# AdbTools

一款基于 WPF 和 C# 开发的 Windows 桌面工具，把 ADB 常用命令封装成了图形界面。无线连接、配对、设备管理、应用调试和实时远程控制都能点几下完成，不用再背命令。程序自带 `adb.exe`、远程控制所需的 scrcpy 设备端组件及依赖，下载后即可直接使用。

## 功能特性

- **无线连接**：填入 `IP:端口` 就能连上设备，端口可以省略，默认使用 `5555`。
- **无线配对**：配对窗口顶部的切换条提供「扫码配对」和「配对码」两种方式，进入时默认是扫码。扫码配对由工具生成二维码，协议与 Android Studio 一致，手机在「使用二维码配对设备」界面扫一下就会自动完成配对，连接在后台静默尝试；也可以切到「配对码」，手动填写 `IP:端口` 和配对码。配对成功后直接关闭配对窗口即可，不必等连接结果。
- **连接管理**：设备列表直接用 `adb devices -l` 拉取，品牌与型号随设备出现就能看到，不必等属性读取。每行用琥珀色「USB」或翠绿色「WiFi」徽标区分连接方式，下方显示设备 SDK 版本。支持一键刷新 `F5`、定时刷新、断开单个设备和断开全部设备。定时刷新可选关闭、3 秒、5 秒、10 秒、15 秒、20 秒、30 秒或 60 秒，设置会自动保存。
- **历史记录**：成功连接的地址会自动保存，展开下拉框右键某条记录即可删除这一条或清空全部记录。
- **应用安装**：右键设备行选择「安装应用」挑选 APK，也可以把 APK 文件直接拖到设备行。支持 `.apk`、`.apk.1` 等改名文件，拖入文件夹会递归收集，最多枚举 5000 个文件、加入 500 个 APK，按全路径去重，超出时在状态栏提示。安装列表是一个独立的非模态窗口，会在后台解析应用名、包名、图标、大小、版本号和最低 SDK 版本，默认全选，支持全选、反选以及随时添加或删除，删除需二次确认，安装期间禁止增删。列表为空时显示引导提示，可以直接点「添加」或把 APK 拖到列表区域。设备 SDK 会读取并显示在窗口顶部，应用要求的最低 SDK 高于设备时，该项标红、标注「不兼容」、禁止勾选，悬停可看到具体原因。安装中锁定选择并自动滚动到当前项，成功后自动取消勾选，失败与跳过项保留选中便于重试。列表下方只在安装结束时显示一条结果汇总，成功为绿色、失败为红色、跳过为橙色，点击「失败 N」打开失败详情。中文路径与 adb 输出按 UTF-8 解码，安装明细按天写入日志。
- **应用列表**：独立窗口打开，显示应用名、包名、图标，以及系统服务、Debug、停用、卸载等状态，支持搜索和按状态筛选。复选框与 `Ctrl` / `Shift` 选择双向同步，普通单击不会误改选择，点击单行操作后会自动收敛为仅选中当前项，避免操作对象不明确。顶部按「选择」和「操作」两组排布，按钮带标准悬停提示，未选择时点击操作按钮会在左下角给出红色提示。批量停用、启用、卸载、强制停止、清除数据、解析名称按顺序执行，只确认一次，支持执行中停止并给出结果汇总。系统应用卸载后仍留在列表中，可以一键恢复。同一台手机只保留一个列表窗口。
- **设备调试**：可以打开 Shell 窗口和独立日志窗口，日志窗口支持缓冲切换、级别与关键字过滤、暂停、清空、保存、自动换行、选择复制。还能一键抓取崩溃日志与诊断包，并把 TCP 端口、分辨率、DPI、显示状态恢复为默认值，其中「显示」会一次恢复分辨率和 DPI。
- **文件管理**：独立窗口浏览设备文件，默认进入 `/sdcard`。顶部图标工具栏提供返回上级、根目录、SD 卡、临时目录、应用数据、刷新和路径跳转，都配了快捷键；右键菜单按「当前文件夹」和「选中项」分组，提供打开、下载、上传、新建、重命名、删除与解析应用。本地文件或文件夹可以直接拖拽上传，上传下载都支持文件与文件夹并保留子目录，空文件夹也会创建；按住 `Ctrl` 划过列表可以快速多选。传输逐文件执行，遇到同名文件会弹窗询问覆盖、跳过、重命名或取消，并可勾选「为后续所有冲突执行此操作」。过程中进度条显示「已完成 / 总数」，状态栏只显示当前项，结束后统一汇总文件与文件夹各自的数量，随时可以点右下角「取消」中止。拖拽到列表时会先提示将上传的文件夹数与文件数。列宽按比例锁定，名称 45%、类型 10%、大小 12%、时间 19%、权限 14%，随窗口自适应，列头不可拖动，也不会出现横向滚动条；权限不足或分区只读会给出明确提示。列表按扩展名区分 29 类文件图标，涵盖文档、表格、压缩包、影音、源码、字体、证书、镜像、3D 模型等，一眼就能认出类型。
- **应用私有数据，无需 root**：工具栏「应用数据」会列出全部第三方应用并探测可访问性。左键双击可调试应用进入它的 `/data/data/<包名>` 目录，之后可以浏览、上传、下载、新建、重命名、删除，全程走 `run-as` 官方调试通道，不需要 root。应用列表支持多选批量下载各应用的私有数据，逐应用切换身份，root 设备直接整目录拉取，不可访问的应用自动跳过；上传、新建、重命名、删除需要先进入对应目录。正式签名包会被标记为「不可访问」。
- **实时远程控制**：右键设备行即可打开实时画面窗口，支持触摸、滑动以及返回、Home、任务、音量、电源等虚拟按键。设备端用 MediaCodec 主动编码，通过 scrcpy server 输出 H.264，画面横竖屏自动适配。顶栏提供截屏和录制两个按钮，截屏得到设备原始分辨率 PNG，录制直接保存原始码流封装成 MP4，不做重编码，体积与系统录屏相当，产物按设备分目录存放在 `%APPDATA%\AdbTools\RemoteCaptures\<设备名>\Screenshots|Recordings`。内置原画、1080P、720P、480P、360P 五档采集分辨率，带清晰度图标与悬停说明；设备达不到的档位自动隐藏，编码器不兼容时逐级向下验证，直到找到可用档位，全部失败时自动回退 `adb screenrecord`。状态栏显示真实上屏帧率，启动与息屏会在画面中央给出卡片提示；关闭窗口后窗口立即消失，停止取流与清理设备端服务在后台完成。同一台设备只保留一个远程控制窗口，重复打开会还原到前台。
- **操作日志**：独立日志窗口记录操作过程与状态，可以右键复制命令。
- **统一对话框**：提示与确认统一使用自绘对话框，没有系统边框，标题栏可以拖动，宽高随内容自适应，宽度在 300 到 620px 之间，正文自动换行且超长可滚动。确认框的主按钮文案按操作定制，例如删除、清空、卸载、断开、打开，危险操作使用红色主按钮。`Enter` 触发主按钮，`Esc` 或「取消」关闭，正文可以 `Ctrl+C` 或右键「复制全部」。启动失败、未捕获异常与系统通知兜底仍然保留系统对话框。
- **托盘后台**：关闭主界面后收起到系统托盘，继续在后台刷新设备。设备连接与断开、安装结果、远程控制断开、配对结果可以分别开关系统通知，前台和后台都会提醒。安装结果通知带设备名、耗时与逐条成功失败明细，通知被关闭或系统发不出去时会用对话框兜底，结果不会丢；配对结果被关闭或通知不可用时完全静默。托盘右键菜单可以显示主界面、刷新设备、直接打开某台设备的远程控制、应用列表或 Shell 窗口，断开指定设备或全部设备，检查更新与退出，退出时直接结束不再确认。再次启动程序会唤出已收起的主窗口，不会产生第二个进程。
- **其它**：窗口置顶、最小化、关于信息、项目地址与镜像地址、检查更新，以及从关于菜单直接打开配置文件夹，日志、设备日志、缓存、截图录像与数据库都在其中，结构见 [配置文件夹](#配置文件夹)。

## 开发环境

- 开发工具：Visual Studio 2019 / 2022
- 框架：`.NET Framework 4.6.2`
- 平台：`x64`
- 主要依赖：`QRCoder` 用于扫码配对，`System.Data.SQLite` 用于应用缓存，`Hardcodet.NotifyIcon.Wpf 2.0.1` 提供系统托盘与气泡兜底，`Microsoft.Toolkit.Uwp.Notifications 7.1.3` 负责 Windows 系统通知，`libwebp` 负责图标解码

## 运行环境

- 需要 `.NET Framework 4.6.2` 运行时。Win10 1607 及以上和 Win11 已内置，无需另装。
- 需要 64 位 Windows 系统。
- 程序已内置 `adb.exe` 及其依赖 `AdbWinApi.dll`、`AdbWinUsbApi.dll`、`QRCoder.dll`、`libwebp.dll`、`System.Data.SQLite.dll`，以及远程控制所需的 `scrcpy-server` 和授权文件 `scrcpy-LICENSE.txt`、`THIRD_PARTY_NOTICES.txt`，还有本项目许可证 `LICENSE.txt`。电脑无需另行安装 ADB、scrcpy 或 VC++ 运行库，Windows 10/11 开箱即用。adb 命令会自动拉起自带服务，不依赖系统中已存在的 adb 服务；Win7/8/8.1 需要系统已安装 Universal C Runtime 更新。
- 远程控制要求设备允许 `adb shell` 以 shell 身份启动 `app_process`，部分深度定制的 TV ROM 会限制这一行为。不满足时程序自动回退到 `adb screenrecord`，功能仍然可用，但流畅度会下降。

## 连接准备

[观看视频](/docs/videos/1.mp4)

### 开启开发者模式

进入 `设置 - 关于 - 版本号`，连续点击 `7 次` 即可开启开发者模式。

### 安卓 11 及以上

进入 `设置 - 系统 - 开发者选项`，找到 `无线调试`，连接 WiFi 后开启，再进入 `无线调试` 查看 `IP 地址和端口`，用这个地址就能无线连接。

> 注：部分设备的入口位置不同，请自行寻找。

### 安卓 11 以下

连接 WiFi 后查看设备的 `局域网 IP 地址`，用这个地址即可无线连接，此时无需输入端口号。

> 注：过低版本的设备可能无法连接。

## 安装和使用

提供自包含的单文件安装程序 `AdbToolsInstaller.exe`，具备以下特性：

- **单个 exe 直接安装**，无需先解压。
- 在「程序和功能」中始终保持**唯一条目**，不同版本不会重复出现。
- 升级时自动读取上次安装位置并**覆盖到原目录**。
- 在桌面与开始菜单创建名为 **`Adb连接工具`** 的快捷方式。
- 通过安装目录下的 `uninstall.exe` 或「程序和功能」即可**干净卸载**。

安装包内含以下文件，安装后位于程序目录：

| 文件 | 用途 |
| --- | --- |
| `AdbTools.exe`、`QRCoder.dll` | 主程序与扫码配对 |
| `Hardcodet.NotifyIcon.Wpf.dll` | 系统托盘图标与通知气泡，在 Toast 不可用时兜底 |
| `Microsoft.Toolkit.Uwp.Notifications.dll` | Windows 10/11 系统通知（Toast） |
| `adb.exe`、`AdbWinApi.dll`、`AdbWinUsbApi.dll` | ADB 及 USB 依赖 |
| `libwebp.dll` | 应用图标 WebP 解码 |
| `System.Data.SQLite.dll`、`SQLite.Interop.dll` | 应用名、图标与系统服务缓存数据库 |
| `scrcpy-server` | 远程控制的设备端取流服务，运行时推送到设备 `/data/local/tmp/` |
| `scrcpy-LICENSE.txt`、`THIRD_PARTY_NOTICES.txt` | 第三方许可证全文与许可、组件声明 |
| `LICENSE.txt` | 本项目 Apache-2.0 许可证全文，含版权声明 |
| `uninstall.exe` | 卸载程序 |

安装时会额外写入 `install.manifest` 记录本次释放的文件清单，卸载时按清单精确删除，不会误删目录内的其他文件。

需要重新生成安装包时，在 Visual Studio 中直接生成 `AdbToolsInstaller` 项目即可，它会自动编译主程序与卸载器、打包并嵌入 payload。脚本 `build_payload.ps1` 会收集主程序输出目录下的全部 `*.exe` 和 `*.dll`，包括 `libwebp.dll`、`SQLite.Interop.dll`，以及运行配置 `AdbTools.exe.config` 和上表中的非程序文件，一并纳入 `payload.zip`。

### 软件更新

- 顶部「关于 → 检查更新」会从 Gitea 仓库镜像读取最新版本号与安装程序。
- 发现新版本时，顶栏右侧出现升级图标。确认更新后，下载进度百分比会显示在图标右侧，平时隐藏，鼠标悬停图标也能看到文字进度。
- 安装包下载到 `%APPDATA%\AdbTools\cache`，与其它临时文件统一管理，不占用 `%TEMP%`；下载完成后自动启动安装程序并退出本程序。
- 覆盖安装会保留 `%APPDATA%\AdbTools\AdbTools.config` 中的配置与连接历史。
- 每次启动会清空 `cache` 目录，残留安装包不会累积。
- 下载目录位于当前用户目录，无需管理员权限；安装程序覆盖程序目录时按系统提示授权即可。

## 使用说明

### 设备配对：Android 11 及以上

配对窗口顶部有「扫码配对 / 配对码」切换条，进入时默认是扫码配对。

**方式一：扫码配对，推荐且为默认方式**

1. 点击「配对」或按 `F8` 打开配对窗口，默认就是扫码界面。
2. 工具会生成配对二维码，协议与 Android Studio 一致，上方高亮条会提示手机上的操作路径。
3. 手机在「无线调试 - 使用二维码配对设备」界面扫描二维码，工具自动发现设备并完成配对。配对成功后配对窗口直接关闭，不弹提示，后台自动尝试连接最多 3 次，不必等待，是否连上以设备列表为准。

> 注：部分老设备的 ADB Wi-Fi 版本较低，v1.0 配对能力受限，扫码失败时请改用方式二。

**方式二：输入配对码**

1. 在配对窗口点击「配对码」切换到手动模式。
2. 在设备的「无线调试 - 使用配对码配对设备」中获取 `IP:端口` 与配对码。
3. 填入**配对地址**与**配对码**，点击「配对」或按 `Enter` 完成。

### 设备连接

1. 在「IP 和端口」输入框填入设备的 `IP:端口`，端口可以省略，默认 `5555`。
2. 点击「连接」或按 `Enter`，等待连接成功。

### 历史记录

- 连接成功的地址会保存在下拉历史中。
- 展开输入框右侧的下拉框，右键某条记录可以「删除记录 / 清空所有记录」。

### 设备列表操作

右键已连接设备，可以进行以下操作：

| 菜单 | 说明 |
| --- | --- |
| 安装应用 | 打开独立的非模态窗口列出 APK，后台解析名称、图标与最低 SDK；支持全选、反选、添加、删除、拖拽添加，并按全路径去重，安装前拦截 SDK 不兼容项；列表下方显示安装结果，点击 `失败 N` 查看失败详情 |
| 远程控制 | 打开实时画面与输入控制窗口，详见[远程控制](#远程控制) |
| 文件管理 | 浏览设备文件，支持上传下载文件与文件夹，详见[文件管理](#文件管理) |
| 应用列表 | 查看全部应用，支持搜索、筛选、单行操作与多选批量操作，包括停用、启用、卸载、强制停止、清除数据、解析名称；单行操作后自动只选中当前项，已卸载的系统应用可以恢复 |
| Shell 窗口 | 打开命令行 Shell，使用外部系统控制台 |
| 断开设备 | 断开当前设备，需二次确认 |
| 查看日志 - 实时日志 / Debug 日志 | 打开独立日志窗口，支持缓冲切换、级别与关键字过滤、暂停、清空、保存、自动换行与选择复制 |
| 查看日志 - 抓取崩溃日志 | 导出 crash 缓冲区到 `%APPDATA%\AdbTools\DeviceLogs\<设备名称>\` |
| 查看日志 - 抓取诊断包 | 打包 logcat、crash、dropbox、内存、CPU 与设备信息为 zip |
| 查看日志 - 打开日志目录 | 打开当前设备的日志文件夹 |
| 恢复默认 - TCP 端口 / 分辨率 / DPI / 显示 | 还原设备默认设置，「显示」会同时恢复分辨率与 DPI |
| 断开所有设备 | 断开全部连接 |

> APK 可以直接拖到设备行，拖入文件夹会递归收集 `.apk` 与 `.apk.1` 等改名文件，按全路径去重，最多枚举 5000 个文件、加入 500 个 APK。安装列表独立且非模态，安装期间主界面可以继续使用。列表中可添加或删除 APK，删除需二次确认，支持全选、反选，也可以把 APK 或文件夹拖到列表区域追加，已存在的会提示「已添加过」。设备 SDK 随设备信息读取并显示在列表顶部；解析出应用最低 SDK 后，高于设备版本的项会标红并显示「不兼容」，禁止勾选，悬停可看到具体原因，安装时自动排除。安装中锁定勾选并逐项滚动到当前项，可以随时取消，剩余项标记跳过。成功项自动取消勾选，失败与跳过项保留选中，点击「再次安装」只重试这些项。安装结束后列表下方才出现一条结果汇总，成功绿、失败红、跳过橙，点击「失败 N」打开详情窗口，按应用显示图标、名称、包名和失败原因，支持单项复制和复制全部。

### APK 安装列表

右键设备 →「安装应用」，或把 APK、文件夹拖到设备行，即可打开独立的非模态安装列表窗口。

**窗口结构**：顶部显示当前设备与 SDK 版本；中部是 APK 列表；底部左侧为「全选 / 反选 / 添加 / 删除」，中间显示「共 N 项 · 已选 M 项」，右侧为「开始安装 / 取消」。

**列表项**：左侧是复选框与图标，右侧上下两行显示应用名与包名，单行超出时省略，悬停可看到完整应用名与文件路径；下一行是「大小 / SDK ≥ N / 版本 X / 解析」四个徽标，最右是安装状态。应用名、图标、包名、版本号与最低 SDK 都在后台从 APK 读取，不下载整包，中文路径按 UTF-8 解码。

**空列表**：列表为空时显示「暂无 APK 文件」引导提示，包含添加按钮与拖放说明，添加文件后自动切回列表。

**增删与去重**：「添加」支持多选文件，也可以把 APK 或文件夹直接拖到列表区域追加。文件夹会递归收集 `.apk`、`.apk.1` 等改名文件，最多枚举 5000 个文件、加入 500 个 APK，超出部分在状态栏提示。两种入口都按**文件全路径**去重，重复项会提示「已添加过」。「删除选中」移除当前勾选的项，需二次确认。安装期间两个按钮与拖放都会被锁定，并给出提示。

**SDK 兼容性**：设备 SDK 随设备信息一起读取并显示。每个 APK 的最低要求高于设备版本时，该项标红、状态显示「不兼容」、禁止勾选，悬停状态可以看到「应用要求最低 SDK N、当前设备 SDK M」的具体原因，安装时自动排除，不占用安装队列。

**安装与结果**：点击「开始安装」后锁定勾选，逐项串行安装并自动滚动到当前项；可以随时取消，剩余项标记跳过。成功后自动取消勾选，失败与跳过项保留选中，点「再次安装」只重试这些项。安装结束后列表下方才出现一条居中的结果汇总，点击「失败 N」打开详情窗口，查看每个应用的图标、名称、包名与失败原因，支持单项复制和全部复制。

### 应用列表

右键设备 →「应用列表」。列表以独立窗口打开，不依附主界面，可以单独最小化或拖到另一块屏幕；同一台手机只保留一个窗口，重复点击会把已打开的窗口带到前台。

**选择与批量操作**：每行左侧复选框可以勾选，也支持 `Ctrl` / `Shift` 选择并同步复选框，普通单击不会误改选择状态。点击行内「停用 / 启用 / 卸载 / 更多」等操作后，会自动恢复为仅选中当前项，避免不清楚操作对象。顶部左侧是「全选 / 反选 / 清空选择」，右侧是「停用 / 启用 / 卸载 / 强制停止 / 清除数据 / 解析名称」，按钮带标准鼠标悬停说明。未选择就点击操作按钮时，底部状态栏显示红色提示。批量操作按顺序逐项执行，只确认一次，完成后汇总成功与失败数量及失败原因，执行中可以点「停止操作」在当前命令结束后退出；清除数据期间会暂停应用名解析，避免争抢设备 IO。

包名与状态来自设备端命令，但**应用名需要额外拉取数据**：

- **包名与状态**：`pm list packages -f` 取包名与 APK 路径，`-s` 和 `-d` 分别标记系统应用与已停用应用，`-u` 用于发现已从手机上移除的系统应用，返回很快。
- **应用名**：Android 没有直接查询应用名的命令，只能读取每个应用 APK 内的 `AndroidManifest.xml` 与 `resources.arsc`，在本机解析 `android:label`，并优先取简体中文资源。
- **系统服务**：解析 manifest，把系统应用中「无桌面入口」或「声明常驻 persistent」的应用标记为「系统服务」，列表用橙色标签显示并支持筛选。
- **Debug 标记**：从 `dumpsys package` 的 `DEBUGGABLE` 标志读出，显示为绿色标签，可以用「Debug 应用 / 非 Debug 应用」筛选。列表先显示、标记后异步回填，不阻塞；每次刷新重新读取，不用缓存。标签只表示 manifest 声明了 debuggable，不代表 run-as 一定能进入私有目录。
- **图标**：与名称一起解析，取 APK 里最高密度的图标位图。自适应图标 `mipmap-anydpi-v26/*.xml` 会再读它的前景层；WebP 与 VectorDrawable 矢量图图标由本机解码或渲染后缓存。解析不到图标的少数应用显示「包名首字 + 固定色块」占位，取到图标后色块自动隐藏，透明背景的图标不会透出底色，也不影响其它信息。
- **拉取量**：每个应用只取 manifest、资源表和一张图标，多数几十 KB 到几百 KB，**不下载整个 APK**。325 个应用首次约需 1 到 2 分钟，状态栏显示进度；可以随时点「停止获取名称」中断，关闭窗口也会立即停止。
- **大应用较慢**：资源表特别大的应用，例如系统「设置」约 104MB，单个约需 1 分钟；超过 160MB 的直接跳过，只显示包名。
- **缓存按设备隔离**：名称、系统服务标记、解析状态与图标都存在 `%APPDATA%\AdbTools\data\AdbTools.db` 的 SQLite 数据库中，并按设备键分开。同一个包在不同手机上名称或图标不同时各自保存，互不覆盖；来自缓存的行会在列表中以「缓存」标签标注。
- **图标去重**：图标内容按 SHA1 存一份，多个应用共用同一张图，或同一应用在多台设备上图标相同，都只占一份空间；无人引用的图标会在下次打开列表时清理。
- **解析名称**：右键某个应用可选「解析名称」，顶部也支持对已选应用批量解析；会忽略已有缓存与失败标记，从设备重新解析并覆盖，用于应用更新后名称变化的情况。
- **远程控制窗口尺寸**：手动调整过的窗口**大小**按设备保存在同一个库，横屏与竖屏各一份，下次打开同一台手机直接沿用；不记位置，恢复时按屏幕居中并把尺寸限制在工作区内，不会跑到屏幕外。
- **设备键**：依次取 `ro.serialno`、`ro.boot.serialno`、`android_id`，都由设备自身返回，同一台手机用 USB、IP 或无线调试连接时结果相同，因此多种连接方式共用一份缓存；三者都取不到时才退回连接序列号，此时各连接方式会各存一份。硬件序列号在设备列表刷新时与品牌型号一并读取，打开应用列表、远程控制时直接使用，不再额外发命令。
- **库结构**：当前为 v2，相比 v1 只新增了远程控制窗口尺寸表，升级时原有缓存不受影响。
- **仍显示包名的情况**：少数系统包本身没有 `android:label`，例如部分 apex 虚拟化组件，只能显示包名。
- **不影响操作**：名称只用于显示，卸载、停用、启用、清除数据等功能随时可用，不必等名称解析完成。
- **WiFi 调试注意**：数据经 adb 通道传输，WiFi 下会占用带宽；解析期间同时使用远程控制可能互相影响，可以先点「停止获取名称」。

### 文件管理

右键设备 →「文件管理」，托盘菜单同样有入口，以独立窗口浏览设备文件，同一台设备只保留一个窗口。

**顶部工具栏**按功能分四组，用竖线分隔：

| 分组 | 按钮 | 说明 |
| --- | --- | --- |
| 导航 | 返回上级 / 根目录 / SD 卡 / 临时目录 / 应用数据 / 刷新 | 分别跳到上级目录、`/`、`/sdcard`、`/data/local/tmp`、应用私有数据列表、刷新当前目录；已在 `/` 时「返回上级」按钮禁用 |
| 地址 | 路径输入框 + 箭头 | 输入路径后按 `Enter` 或点箭头跳转 |
| 文件操作 | 新建文件夹 / 上传文件 / 上传文件夹 / 下载 | 目标都是当前目录 |
| 修改 | 重命名 / 删除 | 作用于选中项，删除不可恢复 |

> 列表右键菜单提供同样的操作，并按「当前文件夹」和「选中项」分组标明作用对象：上传、新建落在当前目录，重命名、删除作用于选中项。右键未选中的行会自动改为只选中该行，右键已选中的行则保持多选。

**快捷键**

| 按键 | 作用 |
| --- | --- |
| `Enter` | 在路径输入框中跳转到输入的路径 |
| `F5` | 刷新当前目录 |
| `Backspace` | 返回上一级 |
| `Delete` | 删除选中项，需二次确认且不可恢复 |
| 双击 | 文件夹进入；文件直接下载 |
| `Ctrl` / `Shift` + 单击 | 追加 / 连续多选 |
| `Ctrl` + 按住左键划过 | 划过经过的项逐个追加选中 |

> 所有窗口的滚动条统一收窄为 8px。

- **浏览**：默认打开 `/sdcard`。左键双击文件夹进入，双击符号链接时先解析目标，指向目录就进入、指向文件则下载。右键弹出分组菜单，不会像双击那样进入目录。
- **解析应用**：在应用列表或包名文件夹上右键「解析应用」，从设备重新读取应用名与图标并覆盖缓存，不重列列表；支持多选，只处理其中可解析的项。
- **上传**：「上传文件」可以一次选多个文件，「上传文件夹」上传整个目录，目标都是当前目录；也可以直接把本地文件或文件夹**拖拽**到文件列表区域上传。目录会逐层创建设备端文件夹，**空文件夹同样会创建**，子目录结构完整保留。设备上**已存在的文件夹不再重复创建**，但仍计入文件夹总数，汇总里只提示已存在，不算「新建文件夹」。
- **下载**：选中一项或多项后点「下载」，再选择本地目录。下载文件夹同样保留子目录结构，会在目标目录下创建同名文件夹，空文件夹也会创建；本地已存在的同名文件夹直接合并，仍计入文件夹总数，但汇总里只提示已存在，不算「新建文件夹」。**文件夹名含逗号**同样可以正常下载，逐文件取回后在本地还原目录结构。
- **新建 / 重命名 / 删除**：顶部对应按钮，删除会二次确认并列出待删项目；支持多选批量删除，过程中进度条显示「已完成 / 总数」，可以随时点右下角「取消」中止。新建与重命名使用统一输入窗口：说明文字过长自动换行，输入框最少 3 行、最多 10 行，超出后内部滚动，校验错误显示在输入框下方，不会覆盖上方说明。
- **传输方式**：上传和下载都是**逐文件执行**。开始前先扫描出文件与文件夹总数，进度条为胶囊造型，显示「已完成 / 总数」，状态栏只显示当前项与完成数；整批结束后统一汇总「文件 x/y，文件夹 m/n」，以及已新增、已覆盖、已重命名、已跳过、失败的数量。文件按「新增」统计、文件夹按「新建」统计，目标处已存在的文件夹只提示已存在。可以随时点右下角「取消」中止整批。失败项会汇总提示，最多列出 10 项，取消后设备端可能残留半个文件。
- **拖拽提示**：把本地内容拖到列表区域时，中央会提示「松手上传 N 个文件夹、M 个文件」；不含可上传内容、正在传输或处于应用列表时给出对应的红色提示，且不允许放下。空目录提示层同样可以直接拖放上传。
- **权限**：`/sdcard`、`/sdcard/Download`、`/sdcard/DCIM` 等可以直接读写。`/data/local/tmp` 属 `shell` 用户，是系统分区里唯一可自由读写的位置，常用作脚本与 APK 的中转。`/data/data`、`/data/system` 是应用私有数据，普通 shell 没有权限，可以改用「应用数据」入口，仅限可调试应用，见下节。`/system`、`/vendor` 只读，写入会提示分区只读。
- **列宽**：各列按比例锁定，名称 45%、类型 10%、大小 12%、修改时间 19%、权限 14%，窗口缩放时自动伸缩；列头不可拖动，也不会出现横向滚动条。
- **图标**：按扩展名区分 **29 类矢量图标**，涵盖文档、表格、演示、PDF、电子书、Markdown、网页、配置、字体、二进制、脚本、证书、字幕、镜像、3D 模型、设计稿、日历、联系人、图片、视频、音频、压缩包、APK、数据库、源码等，未知类型用普通文件图标；文件夹与符号链接各有专用图标。
- **提示位置**：无权限、目录不存在、空目录等结果会**直接显示在列表区域中央**，包含路径、原因与处理建议，并提供「返回上级 / 刷新」按钮。
- **注意**：WiFi 连接下大批量传输会占用带宽，同时使用远程控制会掉帧；传输过程中关闭窗口会先确认再取消。

### 同名文件冲突

上传或下载时，如果目标位置已存在同名**文件**，会弹出冲突询问窗口；同名文件夹直接合并，不询问。窗口为无边框圆角卡片，带投影，标题栏空白处可以拖动：

| 选项 | 说明 |
| --- | --- |
| 覆盖 | 用源文件替换目标文件 |
| 跳过 | 保留目标文件，跳过这一项 |
| 重命名 | 保留两者，自动生成不重名的新名字，如 `报表 (1).xlsx` |
| 取消 | 中止本次全部传输；只跳过当前文件请点「跳过」，该按钮与文件管理器右下角的「取消」同名同色 |

- 窗口显示**源**与**目标**两侧的文件名、大小与修改时间，并用「电脑端」或「设备端」标识区分目标在哪一侧。上传时目标在设备端，下载时目标在电脑端。文件名过长时自动换行，不会用省略号截断。
- 类型不一致时不提供「覆盖」，例如目标处是文件夹而源是文件，只能跳过或重命名。
- 「为后续所有冲突执行此操作」**默认不勾选**，勾选后本批剩余冲突统一按本次选择处理。
- 结束后的汇总分别统计**已新增**、**已覆盖**、**已重命名**、**已跳过**、**失败**，其中已新增会把文件与文件夹分开统计，与「文件 x/y，文件夹 m/n」的进度一一对应。

### 应用私有数据，无需 root

`/data/data` 属 `root` 所有，`adb shell` 连列目录都不允许，所以无法像普通目录那样逐级点进去。工具栏「应用数据」按钮改为两级视图：

1. 进入后列出设备上的**全部第三方应用**，并逐个用 `run-as <包名> id` 探测可访问性，4 个并发，十几二十个应用约 1 秒。可访问的排在前面并显示 uid，不可访问的灰显并标注「需 root」。
2. 左键双击可访问的应用进入它的 `/data/data/<包名>`，之后浏览、新建、重命名、删除、上传、下载都以**该应用自身身份**执行。右键用于「解析应用」，不进入；在列表里多选应用后右键「下载应用数据」可以批量导出。

| 能力 | 说明 |
| --- | --- |
| 前提 | 应用必须是**可调试包**，也就是 manifest 里声明了 `android:debuggable="true"`，这是 Android 官方 `run-as` 通道的限制。微信、银行等正式签名包读不到，需要 root 设备 |
| 浏览 | 目录、文件、权限、大小、时间与普通视图一致；文件操作需先双击进入应用目录 |
| 下载 | 走 `adb exec-out run-as <包名> cat` 二进制流，数据库、图片、二进制文件都不会损坏；文件夹会逐层递归取回，保留目录结构 |
| 批量下载 | 应用列表多选应用后右键「下载应用数据」，逐个切换身份取回，各自落在目标目录的同名子目录下；不可访问的应用自动跳过 |
| 上传 | 先 `adb push` 到 `/data/local/tmp`，再以应用身份 `cp` 进目标目录，落地文件属主就是该应用本身，应用可以正常读写 |
| 返回 | 在应用目录根再点「返回上级」回到应用列表，root 设备同样如此，不会落到 `/data/data`。点「根目录 / SD 卡 / 临时目录」，或在路径框输入应用目录之外的路径，会自动退出应用身份、恢复普通 shell |
| 安全提示 | 删除、重命名会二次确认，并提示「这是应用私有数据，可能导致应用崩溃或数据丢失」 |

### 卸载与恢复

- **系统应用**：卸载走 `pm uninstall --user 0`，只是从当前用户下移除，**系统分区里的安装文件不会被删除**。刷新列表后可以在筛选「已卸载应用」里找到它，点「恢复」用 `pm install-existing` 装回来，不需要重新下载 APK，但账号与登录状态已被清除。如果只想暂时隐藏并保留数据，应改用「停用」。
- **第三方应用**：卸载是完整卸载，APK 与数据一并删除，不可撤销，也不会出现在「已卸载应用」里。
- **恢复的前提**：安装文件仍在系统分区，包括 `/system`、`/system_ext`、`/product`、`/vendor`、`/odm`、`/apex`。极少数被厂商 OTA 精简掉的组件，或系统版本过低没有 `install-existing` 命令的设备，恢复会失败并给出具体原因提示。
- **已卸载行的显示**：状态标签为「已卸载」，「卸载」按钮隐藏，主操作按钮变为「恢复」。

### 操作日志

点击菜单「查看日志」或右键设备的日志项，弹出「操作日志」窗口，记录每次操作的结果与状态；右键日志可以「复制命令」便于排查。

### 设备日志窗口

右键设备 →「查看日志 → 实时日志」打开独立日志窗口：

- **缓冲**：main 主日志、system 系统、crash 崩溃、events 事件、全部缓冲；鼠标悬停每一项可以查看该缓冲的用途说明。
- **级别**：全部级别、Debug 及以上、Info 及以上、Warn 及以上、Error 及以上，按 logcat 级别字段过滤。
- **过滤**：按关键字筛选，不区分大小写，修改后自动从最近 5000 行原始日志重建视图。
- **自动换行**：底栏复选框，开启后长日志按窗口宽度换行，不再出现横向滚动条；状态写入全局配置，下次打开沿用。
- **自动滚动**：开启时只显示最近 5000 行并跟随底部；关闭后停止从顶部裁剪，显示上限临时放宽到 20000 行便于回看，重新开启会回到最近 5000 行并跳到底部。窗口打开时只取最近 200 行历史后跟随，避免瞬间涌入大量日志；adb 进程启动与日志读取都在后台线程，减少打开时卡顿。
- **暂停 / 继续**：暂停后仍继续接收，只冻结显示。
- **清空**：清空当前显示，并同步清空设备端对应缓冲区，有确认提示。
- **保存**：导出当前显示内容到 `%APPDATA%\AdbTools\DeviceLogs\<设备名称>\`。
- **选择与复制**：
  - 单击选中一行，`Shift + 单击` 连续多选，`Ctrl + 单击` 点选多行；
  - `Ctrl + C` 复制选中行，未选中时复制当前显示的全部，按显示顺序输出；
  - `Ctrl + A` 全选。
- **颜色**：按 Android Studio logcat 配色区分级别，V 灰、D 蓝、I 绿、W 橙、E 红、F/A 紫；`[adb]` 错误输出为红色。
- **抓取崩溃日志 / 诊断包**：「查看日志」菜单中，诊断包包含 logcat、crash、dropbox、内存、CPU 与设备信息，打包为 zip。
- 接收缓存最多保留 20000 行原始日志，正常显示上限 5000 行，关闭自动滚动时最多 20000 行，超出后按 FIFO 丢弃最早的行；关闭窗口时会结束对应的 adb 进程。

## 远程控制

右键已连接设备 →「**远程控制**」打开实时画面窗口；多台设备可以各自独立开窗口，互不影响。

### 窗口布局

- **顶部**：左侧只显示上屏帧率，按 3 秒滑动平均计算，画面静止时显示「静止」，悬停可以查看分辨率映射、解码帧率与上屏延迟；右侧是**截屏 / 录制 / 1:1** 三个图标按钮与清晰度下拉框。点「1:1」会把窗口调整到当前输出画面的像素尺寸，让画面 1 像素对应屏幕 1 像素，高 DPI 下按实际缩放换算；屏幕放不下时自动缩小并提示实际比例，达到 1:1 时也会提示。
- **中部**：实时画面，横竖屏切换时窗口按新比例自动调整并重新居中。**手动调整过窗口大小后不再自动改尺寸**，横屏与竖屏各记住一份**大小**并按设备保存，下次打开同一台手机直接沿用，恢复时居中且不超出屏幕，切换清晰度也不影响。首帧前与设备息屏时会在画面中央显示同款状态卡片。
- **底部**：返回、Home、任务、音量、电源虚拟按键。音量键**按住会持续调大或调小**，松开即停，不限次数；电源键按住 **< 0.5 秒**为短按，用于亮屏或灭屏，**≥ 0.5 秒**松开时按长按处理，注入 `--longpress`。
- **输入**：点击、拖拽与虚拟按键走 scrcpy 控制通道，按下即注入、拖动时逐条发送移动事件，延迟为毫秒级；控制通道不可用时自动回退 `adb shell input`，此时拖拽改为松手后一次性滑动。
- **滚轮**：在画面上滚动会转换为一次短距离滑动，抬手后由系统产生惯性；连续滚动会合并成一次手势，避免命令排队。

### 清晰度档位

| 档位 | 长边 | 特点 | 建议场景 |
| --- | --- | --- | --- |
| 原画 | 不缩放 | 最清晰，编解码与带宽开销最高 | USB、需要看清细节或截图取材 |
| 1080P 超清 | 1920 | 清晰度很高，开销约为原画的一半 | USB 或 5G Wi-Fi，兼顾清晰与流畅 |
| 720P 高清 | 1280 | 清晰够用，开销约为原画的 1/4 | 2.4G Wi-Fi、低配电脑、设备性能较弱 |
| 480P 标清 | 854 | 偏糊，小字可能看不清 | 网络较差、只需点击操作和看大致画面 |
| 360P 流畅 | 640 | 最低开销，只能看清大块内容与图标 | 网络差、设备性能弱，或只操作界面 |

程序会按设备原生分辨率**自动隐藏根本达不到的高档位**，例如 720P 屏不会列出 1080P。若某档位的编码器不兼容，会**逐级向下实际验证**并移除失败档位，直到找到能正常出画面的档位。设备完全不支持 scrcpy server 时自动回退 `adb screenrecord`。

### 状态与指标

- 状态栏帧率统计的是**真正写进画面的帧数**，不是解码输出数，按 **3 秒滑动窗口**计算，因此不会每秒跳动；超过 3 秒没有新帧时显示「静止」。悬停可以查看分辨率映射、上屏与解码帧率、最大帧间隔与上屏延迟。
- 锁屏但屏幕仍亮时继续取流，方便在锁屏界面上滑动解锁；息屏时画面中央提示「设备已息屏」。
- 启动过程与息屏提示以中央卡片告知。关闭窗口时窗口**立即消失**，停止取流、清理设备端服务与 adb 转发全部转到后台完成，主界面不会卡顿。同一台设备只保留一个远程控制窗口，重复打开会把已有窗口还原到前台。

### 截屏与录制

- **截屏**：走设备端 `screencap`，按**设备原始分辨率**保存无损 PNG，与当前采集档位无关，档位只影响预览清晰度；设备端失败时退回当前显示帧。
- **录制**：直接保存设备编码的原始 H.264 码流并封装为 MP4，**不做二次编码**，文件大小与系统录屏同一量级；分辨率跟随当前采集档位，因此截屏与录屏的清晰度可能不同。
- **准备阶段**：点录制后按钮变琥珀色圆环表示「准备中」，要等设备产出一个关键帧才开始写文件，计时也从第一帧写入开始。若预录缓存里有 2 秒内的关键帧，会直接回带开录，成片可能包含点击前最多 2 秒画面；没有缓存时重建一次取流，通常 1 到 2 秒；6 秒仍无关键帧则自动取消。准备阶段再点按钮即取消，不产生文件。
- **分段**：MP4 单条轨道尺寸固定，横竖屏切换或切换清晰度时会收尾当前文件并以 `_p2`、`_p3` 续录，停止后提示总段数与总时长。
- **无声音**：只录制画面，设备端编码时 `audio=false`。
- **保存位置**：截图在 `%APPDATA%\AdbTools\RemoteCaptures\<设备名>\Screenshots\`，录像在 `Recordings\`，文件名分别为 `Shot_时间_宽x高.png` 与 `Rec_时间.mp4`。`%APPDATA%` 指向哪里、怎么快速打开见 [配置文件夹](#配置文件夹)。
- **收尾**：点停止或关闭窗口都会先把 MP4 索引写完再结束，不会丢文件；只有进程被强制结束时，比如任务管理器结束或断电，才可能出现缺索引的损坏文件。

## 配置文件夹

程序所有用户数据都在 **`%APPDATA%\AdbTools`**。

`%APPDATA%` 是 Windows 的环境变量，指向**当前登录用户**的漫游数据目录，实际路径通常是：

```
C:\Users\<用户名>\AppData\Roaming
```

其中 `AppData` 是**隐藏文件夹**，在资源管理器里默认看不到，手动一层层翻很容易找不到。打开方式任选一种：

1. 程序内：**关于 → 打开配置文件夹**，最省事；
2. `Win + R` 打开「运行」，输入 `%APPDATA%\AdbTools` 后回车；
3. 资源管理器**地址栏**直接粘贴 `%APPDATA%\AdbTools` 后回车，不必先显示隐藏文件；
4. 手动展开 `C:\Users\<用户名>\AppData\Roaming\AdbTools`。

> 配置按 Windows 账户保存，换账户登录看到的是另一份，不会共享。

```
%APPDATA%\AdbTools\
├─ AdbTools.config            配置项（代理、通知开关、关闭方式、设备历史等）
├─ data\
│   └─ AdbTools.db            应用名 / 图标 / 远程窗口尺寸等缓存（SQLite）
├─ logs\                      程序运行日志，按天分文件，每类自动保留最近 7 份
│   ├─ RemoteControl-yyyyMMdd.log
│   ├─ AppList-yyyyMMdd.log
│   ├─ Install-yyyyMMdd.log
│   └─ AppException-yyyyMMdd.log
├─ DeviceLogs\                从设备抓取的日志与诊断包
│   └─ <设备名称>\
│       ├─ crash-yyyyMMdd-HHmmss.txt
│       └─ diagnose-yyyyMMdd-HHmmss.zip
├─ RemoteCaptures\            远程控制窗口的截图与录像
│   └─ <设备名称>\
│       ├─ Screenshots\       Shot_yyyyMMdd-HHmmss_宽x高.png
│       └─ Recordings\        Rec_yyyyMMdd-HHmmss.mp4（多段为 _p2、_p3）
└─ cache\                     运行期临时文件，每次启动自动清空
```

- 各目录**按需创建**，没用过对应功能时不会出现空目录。
- `DeviceLogs` 与 `RemoteCaptures` 都按**设备名称**分目录，名称为品牌加型号，例如 `Xiaomi 13`；同一台设备的两类产物目录同名，方便一起打包反馈。
- 备份或迁移直接复制整个 `AdbTools` 目录即可；只清理空间可以删 `cache`、`logs`、`DeviceLogs`；删除 `data\AdbTools.db` 后会重新建库，应用名与图标缓存需要重新读取一次。

## 常见问题

**Q：连接设备一直失败，应该怎么排查？**

A：先确认设备与电脑在同一局域网，开发者选项与无线调试都已开启，再检查 IP 和端口是否填写正确。

**Q：设备已经连上，为什么列表里没有出现？**

A：Android 11 及以上需要先完成配对再连接；旧版本系统可能不支持无线连接。

**Q：配对窗口自己关掉了，是出问题了吗？**

A：不是。配对成功时配对窗口会**直接关闭且不弹提示**，这是正常现象。此时后台会自动尝试连接最多 3 次并刷新列表，**能否连上以设备列表为准**；如果列表里仍未出现该设备，稍后点「刷新」或按 `F5`，也可以重新点「连接」。需要重新配对时，再点「配对」或按 `F8` 即可。如果窗口没有关闭而是给出了提示，说明配对失败，按提示检查地址、配对码或网络。

**Q：程序双击后无法启动怎么办？**

A：确认已安装 `.NET Framework 4.6.2` 运行时，Win10 早期版本与 Win7/8.1 需要自行安装。

**Q：安装列表里的 APK 为什么标红显示「不兼容」？**

A：该 APK 声明的最低 SDK 高于当前设备系统版本，安装到这台设备上会被系统拒绝，因此列表标红、禁止勾选并自动排除。悬停该项的状态徽标可以看到要求的最低 SDK 与设备当前 SDK。请更换兼容该设备的应用，或升级设备系统版本。

**Q：添加 APK 时提示「已添加过」，可我确实没加过？**

A：安装列表按**文件全路径**去重，同一路径的 APK 不会重复加入。如果确实要安装同一应用的另一个副本，请选择不同路径的文件。

**Q：安装完成后找不到程序在哪里启动？**

A：从桌面或开始菜单的 **`Adb连接工具`** 快捷方式启动即可。

**Q：文件管理里为什么打不开 `/data/data`？**

A：这是系统保护的应用私有目录，`adb shell` 连列目录都不允许。可以点工具栏「应用数据」，用 `run-as` 访问**可调试应用**的私有目录，不需要 root；正式签名包比如微信、银行应用，以及系统应用读不到，需要 root 设备。

**Q：操作已经完成，为什么收不到系统通知？**

A：先确认「设置 → 消息提醒」里对应开关是打开的，再检查 Windows「设置 → 系统 → 通知」中 `Adb连接工具` 没有被关闭。通知中心里显示的应用名由 AUMID 决定，程序启动时会固定写成 `Adb连接工具`。横幅停留多久由「辅助功能 → 显示通知的时长」控制，通知中心里的历史记录不会自动清除，这是系统设计。

**Q：安装结束后只弹出了对话框，没有收到通知？**

A：说明「安装结果」通知被关闭，或系统通知渠道不可用，程序自动改用对话框展示同样的明细，属于预期的兜底行为。

**Q：下载文件夹后为什么多出一层同名目录？**

A：下载文件夹时会在选定目录下创建同名文件夹并放入内容，这是保留原目录结构的预期行为。

**Q：上传同名文件时为什么要一项项询问？**

A：传输是逐文件处理的，遇到同名文件会逐项询问。不想逐个处理时可以勾选「为后续所有冲突执行此操作」，或用「跳过」和「重命名」批量处理。同名**文件夹**不会询问，直接合并，汇总里只提示已存在、不算新建。

**Q：点了「取消」，为什么已完成数没有变化？**

A：被中止的那一项不计入任何统计，既不算跳过也不算失败，汇总里的已完成数只包含真正处理完的项目。

**Q：进度条里的总数为什么比实际文件数多？**

A：进度按「文件 + 文件夹」统计，文件夹不论是否已存在都算一项。完成汇总会把文件与文件夹的数量分开列出，其中已存在的文件夹只提示、不计入「新建」。

**Q：批量删除为什么看不到进度？**

A：批量删除已经接入与传输相同的进度条，显示「已完成 / 总数」并可随时点右下角「取消」中止。新建、重命名这类没有逐项进度的操作不会显示空的进度徽标。

**Q：对话框右上角为什么没有关闭按钮？**

A：统一改为点「取消」或「确定」关闭，键盘可以按 `Esc`；标题栏空白处仍然可以拖动窗口。

**Q：确认框里按回车为什么直接执行了？**

A：主按钮是默认按钮，按 `Enter` 即确认，这是为了减少鼠标操作。不可撤销的操作会使用红色主按钮提示，按 `Esc` 或点「取消」即可退出。

**Q：提示内容太长显示不全怎么办？**

A：正文会自动换行，超过限高后内部滚动；按 `Ctrl+C` 或右键「复制全部」可以复制完整文字。

**Q：远程控制画面好几秒才变一次，是卡住了吗？**

A：静止界面设备端本来就不产帧，帧率会显示 `0 fps`。如果播放视频时画面区域仍然是黑的，通常是 DRM 安全图层，软件层无法捕获，只能改用 HDMI 采集卡。可以先切到「设置」等持续动画的纯 UI 页确认。

**Q：TV 机顶盒远程控制不流畅怎么办？**

A：优先手动切到 720P、480P 或 360P，程序也会在编码器不兼容时自动逐级降档。如果日志提示「回退到 screenrecord」，说明该 ROM 限制了 `app_process`，属于兼容兜底。

**Q：清晰度下拉框里为什么少了几个档位？**

A：设备原生分辨率达不到的档位会在启动时隐藏，验证失败的档位会被移除，属正常行为。

**Q：远程控制提示「系统缺少媒体组件」怎么办？**

A：当前系统未包含 Media Foundation，常见于 Windows N、KN 版或精简系统，安装系统对应的「媒体功能包」后即可正常取流。这与设备连接无关，不必反复检查数据线或网络。

**Q：帧率看着正常，操作却有粘滞感，怎么改善？**

A：状态栏显示的是真实上屏帧率，粘滞主要来自设备端采集编码与 adb 往返，约 100 到 200 ms，切到更低的分辨率档位可以缓解。

**Q：关闭远程控制窗口后，设备端为什么还有残留服务？**

A：关闭时窗口立即消失，停止取流与清理设备端服务、adb 转发都在后台进行，通常需要 1 到 3 秒，期间设备端服务可能短暂残留，属正常现象。

**Q：左侧帧率为什么显示「静止」？**

A：3 秒内没有新帧，可能是画面没变化或设备已息屏，不是卡死；帧率按 3 秒滑动平均计算，不会每秒跳动。

**Q：点录制后为什么要等一下才开始？**

A：设备是变化驱动编码，静止画面不产帧，也就没有关键帧。程序优先用 2 秒内的预录缓存直接开录，否则重建一次取流，通常 1 到 2 秒；6 秒仍无关键帧则自动取消。

**Q：录制时长为什么和点击的间隔对不上？**

A：计时从第一帧写入开始，之前等关键帧的时间不计；如果命中了预录缓存，成片还会包含点击前最多 2 秒画面，可能比点击间隔略长。

**Q：录制出来的分辨率和截图不一样，正常吗？**

A：正常。截屏走设备端 `screencap`，是设备原始分辨率；录屏复用预览码流，受当前清晰度档位限制，需要更高画质请先调高档位。

**Q：录屏为什么没有声音？**

A：当前只录制画面，不采集音频。

**Q：一次录制为什么生成好几个文件？**

A：MP4 单轨尺寸固定，横竖屏切换或切换清晰度时会另起 `_p2`、`_p3`，每段都能独立播放。

**Q：截图和录像保存在哪里？**

A：截图在 `%APPDATA%\AdbTools\RemoteCaptures\<设备名>\Screenshots`，录像在 `Recordings`。

**Q：录制中直接关闭窗口会丢文件吗？**

A：不会。点停止与关闭窗口都会先写完 MP4 索引再结束；只有进程被强制结束时，比如任务管理器结束或断电，才可能得到缺索引、无法播放的文件。

**Q：为什么帧率上限是 60？**

A：继续放开会让设备编码与 PC 解码开销成倍上升，原画档 120fps 在软件解码下不可行；需要更流畅时优先降低清晰度档位。

**Q：点了窗口的 ×，程序为什么没有退出？**

A：程序默认收起到系统托盘继续后台运行，右键托盘图标选择「退出」才会真正退出；也可以在「设置 → 关闭方式」里选「直接退出程序」。

**Q：日志和配置文件放在哪里？**

A：统一在配置文件夹 `%APPDATA%\AdbTools`，用**关于 → 打开配置文件夹**可以直接打开，完整结构见 [配置文件夹](#配置文件夹)。日志按天分文件、每类自动保留最近 7 份，包括 `logs\RemoteControl-yyyyMMdd.log`、`logs\AppList-yyyyMMdd.log`、`logs\Install-yyyyMMdd.log` 和 `logs\AppException-yyyyMMdd.log`，只有当天确实产生日志时才创建。设备日志与诊断包在 `DeviceLogs\<设备名称>\`；配置与设备历史在 `AdbTools.config`；应用名与图标缓存在 `data\AdbTools.db`；临时文件在 `cache\`，每次启动自动清空。
